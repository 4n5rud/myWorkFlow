# 자동 장치

> 지침서의 규칙 중 일부는 사람이나 Claude가 기억해서 지키는 것이 아니라 **장치가 자동으로 지킨다.**
> 무엇이 언제 돌고, 무엇을 막고, 어떻게 끄는지를 여기에 모았다. 장치 동작은 이 문서가 원본이다.

관련 문서: [[00 세션 공통 지침]] §8 (브랜치 규칙), §15 (작업 산출물 위치), [[03 코딩 규칙]] §5 (로컬 목업), [[09 커밋 메시지 규칙]], [[12 받은 자료 정리]], [[13 보낼 문서와 발송 상태]], [[14 할 일과 끝낸 일]], [[15 비밀값 커밋 금지]]

## 1. 한눈에 보기

|---|---|---|---|
| 모든 커밋, 머지, 리베이스, 패치 적용, 푸시 직전(사용자가 직접 한 것 포함) | git 전역 훅 | 비밀값, 공용 저장소의 개인 자료, 커밋 메시지(AI 서명, 09 제목 규칙), 서브모듈 연결을 검사한다. 읽기 전용 저장소와 커밋 금지 저장소는 막는다. 그다음 저장소의 원래 훅을 이어서 실행한다(8장, [[15 비밀값 커밋 금지]]) | 막음. 커밋 메시지 제목 규칙만 사람이 친 커밋이면 경고만 |
| 명령을 실행하거나 파일을 쓰기 직전 | 안전장치 훅(guard) | 2장 표 | 막거나 확인 창을 띄움 |
| 커밋 명령을 치기 직전 | 커밋 메시지 미리 알림 훅(commit-lint) | 제목이 [[09 커밋 메시지 규칙]]과 다르면 미리 알려 준다. 실제로 막는 것은 git 전역 훅의 커밋 메시지 단계다 | 막지 않음(알림만) |
| 문서를 쓰기 직전 | 문서 쓰기 훅(sent-claims) | 세션 임시 폴더에 html, pdf, 오피스 문서(docx, xlsx, pptx, hwp, key, numbers, pages)를 만들려 하면 막고, md, txt, csv면 사용자가 볼 문서는 `_작업/`에 두라고 알린다(00 §15). 문서(md, txt, html, csv, json)에 "전달함, 발송함, 회신 대기" 같은 표현이 들어가면 사용자가 보냈다고 확인했는지 다시 보라고 알린다([[13 보낼 문서와 발송 상태]]) | 임시 폴더의 html, pdf, 오피스 문서만 막음 |
| 서브에이전트를 띄우기 직전, 시작할 때, 끝날 때 | 서브에이전트 수 제한 훅(subagent-limit) | 시작과 끝을 기록하고, 지금 일하는 서브에이전트가 한도에 닿으면 새로 띄우기를 거부한다. 한도는 `SUBAGENT_LIMIT`(기본 4), 프로젝트별로는 `SUBAGENT_LIMIT_BY_DIR`. 최근 10분 안에 시작했거나 15분 안에 대화 기록이 쓰인 것만 센다(멈춘 일꾼이 자리를 차지하지 않게). 3시간 넘은 기록은 지운다 | 한도에 닿으면 막음 |
| 서브에이전트가 시작될 때 | 서브에이전트 시작 훅 | 전역 지침 전체, 지침서 길잡이 위치, 읽기 전용 저장소와 커밋 금지 저장소 목록, 브랜치 규칙을 넣어 준다(서브에이전트는 전역 지침을 따로 받지 못하므로) | 막지 않음 |
| 사용자가 메시지를 보낼 때 | 받은 자료 훅 | 저장소 밖 파일 경로(다운로드, 바탕화면, 임시 폴더 등)가 들어오면 `_수신함/` 정리, 보안 정보 이중 확인, 상대 경로 사용을 알린다. 대화 캡처 이미지와 시스템 알림은 건너뛴다([[12 받은 자료 정리]]) | 막지 않음 |
| 사용자가 메시지를 보낼 때 | 완료 말 훅 | 끝냈다는 말이 오면 프로젝트 `할 일.md`에서 체크해 `끝낸 일.md`로 옮기라고 알린다. 물음표로 끝나는 질문은 건너뛴다([[14 할 일과 끝낸 일]] §3) | 막지 않음 |
| 사용자가 메시지를 보낼 때, 답을 마칠 때 | 한국어 답 훅 | 메시지마다 "답과 보고는 한국어로" 한 줄을 알린다. 답을 마칠 때 그 답이 영어 문장 위주면(코드, 경로, 링크를 빼고 영문자 150자 이상이면서 한글이 25% 미만) 한 번 되돌려 한국어로 다시 쓰게 한다 | 영어 답만 한 번 되돌림 |
| 세션을 시작할 때(새로 열기, 이어 하기, 비우기, 압축 뒤) | 세션 시작 훅 | 아래 목록 | 막지 않음 |
| 세션을 끝낼 때 | 세션 종료 훅 | 그 프로젝트의 작업 폴더 정리(3장) | 막지 않음 |
| 스킬을 쓸 때마다 | 사용 기록 훅 | 어떤 스킬이 언제 쓰였는지 한 줄씩 기록 | 막지 않음 |
| 매일 `DAILY_HOUR`시(기본 9시, 비우면 등록하지 않음) | 일일 예약 작업(macOS launchd) | 모든 프로젝트 작업 폴더 정리, 설정 기록 저장, 지침서 사본을 노트 보관함에 맞춤(`sync-guides.sh`), 최근 24시간 스킬 사용 집계, 요약 파일과 Mac 알림 | 해당 없음 |
| 매주 금요일 오전 9시 | 주간보고 자동화(Orca) | 이번 주 주간 폴더가 있는 프로젝트마다 주간업무보고 HTML과 PDF를 만듦. 커밋은 안 함 | 해당 없음 |

세션 시작 훅이 알려 주는 것(읽기 전용 저장소에서는 아무것도 하지 않는다):

- 원격보다 몇 커밋 뒤처졌는지. 추적 브랜치가 없으면 확인하지 못했다고 알린다. 원격 받기는 저장소마다 10분에 한 번만 한다(00 §1)
- 서브모듈을 묶는 상위 저장소가 기본 브랜치(main 또는 master)가 아닌 브랜치에 있으면 경고
- 로컬 전용 목록(`_할일/할 일.md`, `_할일/끝낸 일.md`, `_발신함/목록.md`)이 사라졌으면 보관본(Claude 설정 폴더의 `harness/local-lists/`)으로 되살리고 알림. 있으면 보관본을 새로 뜬다
- 할 일 목록에 남은 일의 개수와 위쪽 다섯 줄. 할 일 목록이 없으면 만들라고 알림
- 발송 확인이 안 된(초안, 검토 요청) 보낼 문서
- 압축 뒤면 지침서를 다시 읽고 인계 문서를 갱신하라고 알림(00 §8)
- 길잡이 표에서 빠진 지침서
- 그 프로젝트의 작업 폴더 정리를 뒤에서 시작(3장)

## 2. 안전장치 훅이 막는 것

| 상황 | 동작 |
|---|---|
| 읽기 전용으로 지정한 저장소(`harness.conf`의 `READONLY_REPOS`) 안의 파일을 고치거나 git으로 바꾸려 함 | 막음. 읽기는 허용. 커밋, 머지, 리베이스, 체리픽, 되돌리기, 패치 적용, 푸시는 git 전역 훅도 막아서 사용자가 터미널에서 해도 막힌다 |
| 커밋 금지로 지정한 저장소(`harness.conf`의 `NO_COMMIT_REPOS`)에서 커밋, 푸시, 태그, 머지, PR을 하려 함. 그 저장소의 작업 폴더(워크트리) 포함 | 막음. 파일 수정과 `git status`, `git add`는 허용. 커밋, 머지, 푸시는 git 전역 훅도 막는다 |
| 작업 브랜치(기능, 수정, 핫픽스)에 커밋하고 푸시함 | 통과 |
| 보호 브랜치(`PROTECTED_BRANCHES_RE`, 기본은 dev, develop, main, master, prod, production, staging, stg)로 푸시 | **매번 확인 창.** 창에는 저장소, 올라가는 커밋 목록(최대 8개, 커밋마다 본문 첫 두 줄), 바뀌는 양과 바뀐 파일, 예와 아니오를 고르면 어떻게 되는지, 고르는 기준(리뷰와 테스트 결과를 대화에서 먼저 봤으면 예)이 나온다. 받는 쪽에만 있는 커밋이 있으면 주의를 함께 띄운다. 검사 결과를 먼저 보고받았을 때만 승인한다 |
| 보호 브랜치 위에서 머지, 원격 PR 머지 | **매번 확인 창.** 창에는 어디에 무엇을 합치는지, 실행할 명령, 들어오는 커밋 목록과 바뀐 파일, 예와 아니오의 결과와 고르는 기준이 나온다 |
| 커밋 메시지나 PR 본문에 AI 서명이나 Co-Authored-By | 막음 |
| 커밋에 자격증명으로 보이는 값(키, 토큰, 비밀번호 대입) | 막음 |
| 커밋에 새로 추가한 줄에 개인 절대 경로(`/Users/<이름>/`, `/home/<이름>/`, Windows 사용자 폴더, 임시 폴더) | 막음 |
| 공용 저장소(`WORK_DIR` 아래 프로젝트 저장소) 커밋에 개인 자료: 절대 경로, 노트 보관함 위치, 로컬 전용 목록(`_할일/`, `_발신함/목록.md`) | 막음. git 전역 훅도 커밋 직전에 막는다. 하네스 저장소 자신과 `PERSONAL_REPOS`에 적은 저장소는 뺀다([[12 받은 자료 정리]], [[14 할 일과 끝낸 일]]) |
| 커밋, 푸시, 커밋 메시지, PR 본문에 비밀값이나 키 파일이 있음 | 막음. `.example` 파일과 자리 표시는 허용([[15 비밀값 커밋 금지]]) |
| `--no-verify`, `git commit -n`, `core.hooksPath` 바꾸기(대소문자 상관없음), git 설정 위치를 바꾸는 환경 변수(`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_COUNT`, `GIT_CONFIG_PARAMETERS`, `HOME`, `XDG_CONFIG_HOME` 등)나 `env -i`를 붙인 커밋, 푸시, 머지, 리베이스, 체리픽, 되돌리기, 당겨 오기 | 막음(Claude만. 사용자는 직접 할 수 있다) |
| 훅 스크립트, git 전역 훅, `settings.json`, `harness.conf`, `~/.gitconfig`, 비밀값 허용 목록을 고치거나 지움(파일 도구, 리다이렉션, `tee`, `sed -i`, `cp`, `mv`, `rm`, `perl -i`, 파이썬 쓰기) | 막음(Claude만). 읽기(`cat`, `grep`, `git config --get`)와 밖으로 복사는 허용 |
| `git config`로 전역이나 시스템 설정 쓰기, include 설정(`include.*`, `includeIf.*`) 쓰기 | 막음(Claude만). include로 다른 설정 파일을 끌어와 훅 경로를 바꾸는 길을 막는다 |
| git 훅을 끄고 커밋과 푸시를 하는 문서정리 도구(`tools/doc-cli.mjs` 같은 경로, 한 프로젝트의 도구, 훅이 이 경로로 알아봄)에 넘기는 파일에 비밀값이 있음 | 막음 |
| 커밋이나 푸시에 로컬 전용 목업 파일, 목업을 켜는 설정, `// 로컬 전용` 또는 `LOCAL-ONLY` 표시 줄 | 막음 |
| 목업 설정이나 로컬 설정 파일을 쓴 빌드 명령 | 막음. 개발 실행(`flutter run` 등)은 허용 |

예외 설정(모두 `harness.conf`, 사용자만 고친다):

- `FREE_PUSH_REPOS`: 적은 개인 저장소는 브랜치 규칙을 적용하지 않는다.
- `FREE_BRANCHES_BY_REPO`: `("<프로젝트 폴더>=<브랜치>[,<브랜치>]")` 꼴. 그 프로젝트(안의 서브모듈과 다른 곳에 만든 작업 폴더 포함)에서는 적은 보호 브랜치로 머지와 푸시를 확인 없이 허용한다. main, prod, staging은 넣지 않는 것을 권한다.
- `MOCK_ALLOW_PATHS_RE`: 저장소 기준 경로 정규식에 맞는 파일은 목업 파일 검사에서 뺀다. 개발 서버와 시험이 함께 쓰는 공용 가상 응답(MSW의 `src/mocks/` 등)을 저장소에 두는 프로젝트에만 쓴다. 목업을 켜는 설정과 `LOCAL-ONLY` 표시 줄 검사는 그대로 적용한다. (2026-11-06 기준, 다시 확인 필요. 관리자 웹의 공용 가상 응답 때문에 푸시가 막힌 일로 사용자가 결정)
- `PERSONAL_REPOS`: 적은 저장소는 개인 자료 검사에서 뺀다.
- `SUBAGENT_LIMIT_BY_DIR`: `("<프로젝트 폴더>=<수>")` 꼴. 그 폴더와 그 저장소의 작업 폴더에서 연 세션의 서브에이전트 한도.

## 3. 작업 폴더 자동 정리

장치는 `worktree-gc.sh`다. 세션을 시작하거나 끝낼 때 그 프로젝트(`<WORK_DIR>/<프로젝트>`)를 대상으로 `--apply`를 붙여 뒤에서 돌고, 매일 예약 작업은 모든 프로젝트를 대상으로 돈다. 읽기 전용 저장소는 건너뛴다.

`<WORK_DIR>/<프로젝트>` 안의 작업 폴더(git 워크트리)를 아래 조건을 **모두** 만족할 때만 `git worktree remove`로 지운다. 늘 있는 폴더(dev, stg, prod, main, master, rel-*)는 건드리지 않고, 강제 삭제는 하지 않는다.

- 따로 만든 작업 폴더다(본 체크아웃이나 서브모듈이 아니다)
- dev, main, master 중 하나(원격 기준)에 합쳐졌다. 같은 내용의 커밋이 들어간 것도 합쳐진 것으로 본다
- 커밋이 원격에 있고, 수정 중이거나 커밋 안 한 파일이 없다
- git 밖 파일은 도구가 다시 만드는 생성물이거나, 같은 저장소 dev 폴더의 파일과 내용이 똑같다(`.env`, 키 파일)
- 그 폴더에서 돌고 있는 프로그램이 없고, 60분 넘게 손대지 않았다

미리 보려면 `--apply` 없이 돌린다(`~/.claude/hooks/worktree-gc.sh <프로젝트 폴더>`). 아무것도 지우지 않고 지울 것과 남길 것을 이유와 함께 보여 준다.

남은 폴더는 기록(4장)에 남은 이유(합쳐지지 않음, 푸시 안 됨, dev와 다른 키 파일, 최근에 고침 등)를 보고 사람이 판단한다. 폴더를 손으로 지우거나 옮기지 않고 git으로 한다([[01 커맨드 센터 운영]] §2).

| 매일 정리의 원래 출력 | `~/.claude/logs/daily-gc-last.log` |
| 스킬 사용 기록 | `~/.claude/logs/skill-usage.tsv` |

| 설정 변경 이력 | `claude-config log` (아래 5장) |

## 5. 설정 변경 이력과 되돌리기

**지침서 원본과 사본 (2026-11-16 바뀜):** 지침서 원본은 하네스 저장소의 `guides/`다(harness.conf의 `GUIDES_DIR`). 세션은 여기서 읽고 고치고 커밋한다. 노트 보관함의 지침서(`NOTES_GUIDES_DIR`)는 사본으로, `sync-guides.sh`가 설치와 매일 예약 작업 때 원본에서 한쪽으로 복사한다. 사본에서 고친 것으로 보이는 파일은 덮어쓰지 않고 알린다. 원본을 옮긴 이유는 노트 보관함 폴더를 macOS 개인정보 보호가 자주 막아 세션이 지침서를 못 읽었기 때문이다. 예전 `export-guides.sh`는 쓰지 않는다.

훅, 스킬, 전역 지침, 설정, 메모리는 이 Mac 안의 기록 저장소에 버전으로 남는다(원격 없음). 매일 예약 작업이 바뀐 것을 자동 저장하고, 설치 스크립트도 설치할 때 한 번 저장한다.

```bash
~/.claude/bin/claude-config log --oneline        # 이력 보기
~/.claude/bin/claude-config diff                 # 마지막 저장 뒤 바뀐 것
~/.claude/bin/claude-config save "메시지"         # 지금 상태 저장
```

첫 기록은 2026-11-04 변경 전의 원래 설정이다.

## 6. 끄거나 고칠 때

| 하고 싶은 것 | 방법 |
|---|---|
| 훅 하나를 잠시 끄기 | `~/.claude/settings.json`의 `hooks`에서 해당 줄을 지우거나, Claude Code에서 `/hooks` 메뉴로 끈다 |
| 모든 훅을 잠시 끄기 | `settings.json`에 `"disableAllHooks": true` |
| 매일 예약 작업 끄기 | `launchctl bootout gui/$(id -u)/claude-work-harness.daily` |
| 주간보고 자동화 끄기 | Orca 자동화 목록에서 "주간보고 전체 (매주 금 09:00)"을 끈다 |
| 훅을 고친 뒤 확인 | 하네스 저장소의 원본을 고친 뒤 `install.sh`를 다시 돌린다. 설치 스크립트는 원본을 설치한 다음 `tests`의 시험 묶음을 모두 그 파일로 돌리고, 실패한 묶음은 전체 출력을 보여 준다. 모두 통과해야 한다. `~/.claude/hooks/tests/`의 시험 파일만 따로 돌리면 원본이 아니라 이미 설치된 훅을 시험한다 |
| 실제 설정을 건드리지 않고 시험 설치 | `CLAUDE_HOME=<임시 폴더> bash install.sh` (git 전역 설정, 예약 작업, 설정 기록 저장은 건너뛴다) |
| git 전역 훅 끄기 | `git config --global --unset core.hooksPath` (사용자만. 비밀값 검사가 꺼진다) |

- 훅 파일은 `~/.claude/hooks/`에 있다. Claude는 이 폴더를 직접 고치지 못한다. 하네스 저장소 원본을 고치고 설치 스크립트로 옮기면서 시험한다.
- 시험 명령 안에 읽기 전용 저장소 경로나 AI 서명 문구를 직접 쓰면, 살아 있는 훅이 시험 자체를 막는다. 시험은 파일로 만들어 돌린다.

## 7. 장치가 못 막는 것

안전장치 훅은 명령의 글자 모양을 보고 판단한다. 별칭(alias), 변수에 담은 경로, `find -delete`나 `xargs`처럼 다른 프로그램을 거쳐 실행하면 못 잡을 수 있다. 읽기 전용 저장소와 커밋 금지 저장소의 커밋과 푸시, 비밀값 검사, 개인 자료 검사, 커밋 메시지 검사는 git 전역 훅이 실제 커밋과 푸시에서 한 번 더 막으므로 명령 모양과 상관없이 걸린다. 저장소가 자기 훅 경로(`core.hooksPath`)를 따로 쓰면 그 저장소에서는 git 전역 훅이 돌지 않는다. **가장 확실한 방어선은 원격 서버의 브랜치 보호**(직접 푸시 금지, 머지 리퀘스트로만 합치기)다. (2026-11-04 기준, 다시 확인 필요) 팀 영향 때문에 켜지 않았다.

## 8. git 전역 훅이 단계마다 하는 일

설치 스크립트가 git 전역 설정 `core.hooksPath`를 하네스의 git 훅 폴더로 넣는다(다른 경로가 이미 있으면 바꾸지 않고 알린다). 폴더 안의 훅 이름은 모두 한 파일(`_dispatch`)을 가리킨다.

| 단계 | 하는 일 |
|---|---|
| 커밋 준비, 커밋 직전, 커밋 메시지, 머지 커밋, 리베이스, 패치 적용, 푸시 직전 | 읽기 전용 저장소와 커밋 금지 저장소면 막는다. 저장소는 공유 git 폴더로 비교해서 작업 폴더, `git -C`, `GIT_DIR`로 들어와도 걸린다. 리베이스는 이 저장소에만 있는 커밋을 다시 쓸 때만 막는다 |
| 커밋 직전 | 올릴 내용의 비밀값을 검사하고, 공용 저장소면 개인 자료를 검사한다 |
| 커밋 메시지 | AI 서명을 막고, 메시지의 비밀값을 검사하고, [[09 커밋 메시지 규칙]] 제목 검사를 한다. 제목 검사는 Claude 세션(`CLAUDECODE` 환경 변수가 있음)의 커밋이면 막고, 사람이 터미널에서 친 커밋이면 경고만 하고 진행한다. 검사기가 고장 나면 검사를 건너뛴다 |
| 푸시 직전 | 원격에 없는 모든 커밋의 이력 전체를 비밀값 검사한다. 서브모듈 연결도 검사한다. 상위 저장소가 기본 브랜치(main, master, 원격의 기본 브랜치)로 푸시할 때 서브모듈 포인터가 그 서브모듈의 기본 브랜치에 있는 커밋이 아니면 막고, 기본 브랜치보다 뒤처지기만 했으면 경고한다. 서브모듈이 기본 브랜치로 푸시하면 상위 저장소의 포인터를 갱신하라고 알린다 |
| 그다음 | 저장소의 원래 훅(`.git/hooks/<이름>`, Git LFS, 프로젝트의 비밀값 점검 등)을 이어서 실행한다. 검사할 것이 없는 단계는 원래 훅만 실행한다 |
