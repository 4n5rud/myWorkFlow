# 할 일과 끝낸 일

> 프로젝트마다 **문서 저장소의 `_할일/` 폴더**에 **`할 일.md`**(아직 남은 일)와 **`끝낸 일.md`**(끝낸 일 기록) 두 파일을 둔다. 저장소 폴더에 두지만 커밋하지 않는 로컬 전용 파일이다.
> 날짜와 상관없이 남은 일은 모두 `할 일.md` 한곳에 있다. 끝나면 체크해서 `끝낸 일.md`로 옮긴다.

관련 문서: [[13 보낼 문서와 발송 상태]], [[08 보고 지침]], [[00 세션 공통 지침]] §8 (인계 문서)

---

## 한눈에 보기

| 할 일 | 규칙 |
|---|---|
| 위치 | 문서 저장소 폴더의 `_할일/할 일.md`, `_할일/끝낸 일.md`(로컬 전용, 커밋하지 않음). 노트 보관함 `work/<프로젝트>/`에는 이 두 파일을 가리키는 바로가기만 둔다 |
| 넣을 때 | 이번 대화에서 끝내지 못한 일, 약속한 후속 작업, 막혀서 기다리는 일, 사용자가 정해야 할 일 |
| 뺄 때 | **세션이 처리하고 확인했을 때**, 또는 **사용자가 끝냈다고 말했을 때**(§3) |
| 빼는 법 | `[x]`로 체크하고 그 줄을 `끝낸 일.md` 맨 위로 옮긴다. 끝낸 날과 근거를 붙인다 |
| 누가 고치나 | 그 프로젝트의 **메인 세션만** 고친다. 서브에이전트는 결과를 보고하고, 메인이 반영한다 |

## 0. 위치

- **원본은 프로젝트의 문서 저장소 `_할일/`이다.** `_수신함/`, `_발신함/`과 같은 저장소다. 여러 저장소로 나뉜 프로젝트는 문서를 모아 두는 저장소(상위 저장소나 문서 저장소)에 둔다. 어느 저장소인지는 프로젝트 목록(`projects.md`)의 "문서 저장소" 칸에 적는다.
- 노트 보관함의 `work/<프로젝트>/할 일.md`와 `끝낸 일.md`는 원본을 가리키는 바로가기다. 노트에서 고쳐도 원본이 고쳐진다. 바로가기를 원본으로 착각해 따로 만들지 않는다.
- **두 파일은 로컬 전용이다. 커밋하지 않는다(2026-11-09 사용자 결정).** 공용 저장소에 개인 업무 관리 자료와 개인 노트 위치가 올라가지 않게 하려는 것이다. 저장소 `.gitignore`에 `_할일/`과 `_발신함/목록.md`가 들어 있고, 커밋 검사가 막는다. 원격을 받으면서 지워지면 세션 시작 훅이 보관본(Claude 설정 폴더의 `harness/local-lists/`)으로 되살린다.

## 1. `할 일.md`

```markdown
# 할 일 (<프로젝트>)

> 날짜와 상관없이 이 프로젝트에 남은 일. 끝나면 체크해서 같은 폴더의 `끝낸 일.md`로 옮긴다.

## 세션이 처리할 것

- [ ] 결제 테스트 키를 받으면 개발 서버에 연결 (추가 11.06)
- [ ] 예약 목록 지연 필터를 main에 합치기 전 검사 (추가 11.06, 근거: 검사 전 커밋 7개)

## 사용자 확인 기다림

- [ ] 확인 요청 10건을 보냈는지 (추가 11.06, [[13 보낼 문서와 발송 상태]])
- [ ] 주간보고에 동료 작업을 넣을지 (추가 11.06)
```

- 한 줄에 한 가지만 쓴다. 무엇이 끝나면 끝인지 알 수 있게 쓴다("확인" 대신 "확인하고 결과를 노트에 적기").
- 줄 끝 괄호에 추가한 날과, 필요하면 근거나 관련 문서를 적는다. 경로는 저장소 기준 상대 경로나 위키 링크로만 쓴다([[12 받은 자료 정리]]).
- **"사용자 확인 기다림"**에는 사용자만 답하거나 해 줄 수 있는 일을 둔다. 보낼 문서의 발송 여부, 승인, 결정, 계정이나 키 받기 같은 것이다.
- 우선순위가 있으면 위로 올린다. 날짜순으로 정렬하지 않는다.

## 2. `끝낸 일.md`

```markdown
# 끝낸 일 (<프로젝트>)

> 같은 폴더의 `할 일.md`에서 끝낸 일을 옮겨 온 기록. 새것이 위에 온다. 지우지 않는다.

- [x] 주간보고 커밋과 푸시 (끝냄 11.06, 사용자 "올려도 됨", 커밋 기록 있음)
- [x] 결제 테스트 키 개발 서버 연결 (끝냄 11.06, 결제 시험 통과 확인)
```

- 끝낸 날과 **근거**를 반드시 붙인다. 근거는 둘 중 하나다.
  - 세션이 확인한 것: 시험 통과, 커밋, 화면 확인, 받은 회신
  - 사용자의 말: 사용자가 한 말을 짧게 따옴표로 남긴다
- 새것을 맨 위에 넣는다. 이 파일은 지우지 않고 계속 쌓는다.

## 3. 🔴 언제 체크하나

- **세션이 처리했을 때:** 실제로 끝났는지 확인한 뒤에 체크한다. "고쳤다"는 시험이나 화면으로 확인한 뒤에 쓴다([[02 이슈 세션 운영]] §6). 확인하지 못했으면 체크하지 않고 그 줄에 "(처리함, 확인 전)"을 붙인다.
- **사용자가 끝냈다고 말했을 때:** 사용자가 "완료", "처리했어", "했어", "됐어", "끝났어", "보냈어" 같은 말을 하면 그 말이 근거다. 물음표로 끝나는 질문("됐어?")은 끝냈다는 말이 아니다. 세션이 따로 확인하지 못했어도 체크하고 옮긴다. 사용자의 말을 근거로 남긴다.
- 애매하면(어느 항목을 말하는지 모르겠으면) 항목을 짚어 다시 묻는다.
- 체크하지 않은 줄을 말없이 지우지 않는다. 할 필요가 없어졌으면 "(하지 않기로 함, 사유)"를 붙여 `끝낸 일.md`로 옮긴다.

## 4. 세션이 할 일

- **시작할 때:** `할 일.md`를 읽는다. 세션 시작 훅이 남은 개수와 위쪽 몇 줄을 알려 준다.
- **일하면서:** 새로 생긴 일, 약속한 후속 작업, 사용자 확인이 필요한 일을 바로 넣는다.
- **보고할 때:** 이번에 체크한 것과 새로 넣은 것을 한 줄씩 알린다. "사용자 확인 기다림"이 있으면 함께 묻는다.
- **끝낼 때:** `할 일.md`가 최신인지 본다. 남은 일은 `할 일.md`에, 맥락(함정, 막힌 것, 안 하기로 한 것과 이유)은 인계 문서([[00 세션 공통 지침]] §8)에 둔다. 다음 세션은 이 두 가지로 이어서 시작할 수 있어야 한다.

## 5. 다른 기록과의 관계

| 기록 | 역할 |
|---|---|
| `_할일/할 일.md`, `_할일/끝낸 일.md` | 날짜와 상관없는 남은 일과 끝낸 일. 세션이 일할 때 기준 |
| 주간목표, 날짜별 노트 | 이번 주와 오늘의 계획. 주간보고의 근거 |
| `_발신함/목록.md` | 보낼 문서의 발송 상태([[13 보낼 문서와 발송 상태]]). 발송 여부를 묻는 일은 `할 일.md`의 "사용자 확인 기다림"에도 한 줄 넣는다 |
| 인계 문서(`_작업/인계/`) | 다음 세션에 넘길 맥락(함정, 막힌 것, 안 하기로 한 것과 이유). 남은 일 목록은 두지 않고 `할 일.md`를 가리킨다([[00 세션 공통 지침]] §8) |

같은 일을 여러 곳에 길게 쓰지 않는다. 주간목표와 날짜별 노트에는 할 일 줄을 짧게 옮겨 적거나 링크로 가리킨다.

## 6. 지키는 장치

- **세션 시작 훅:** 그 프로젝트 문서 저장소의 `_할일/할 일.md`에 남은 일이 있으면 개수와 위쪽 몇 줄을 알린다. 파일이 없으면 만들라고 알린다.
- **완료 말 훅:** 사용자 메시지에 끝냈다는 말(§3)이 있으면, `할 일.md`에서 해당 항목을 체크해서 `끝낸 일.md`로 옮기라고 알린다.
- 자세한 동작은 [[10 자동 장치]].
