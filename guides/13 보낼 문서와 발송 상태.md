# 보낼 문서와 발송 상태

> **Claude는 아무것도 보내지 않는다. 보내는 사람은 언제나 사용자다.**
> 그래서 Claude가 만든 문서는 **사용자가 "보냈다"고 직접 말하기 전까지 "작성 완료(발송 전)"**이다. 만든 것을 보낸 것으로 쓰지 않는다.

관련 문서: [[12 받은 자료 정리]] (받은 자료, `_수신함`), [[08 보고 지침]], [[11 주간보고 검수]]

---

## 한눈에 보기

| 할 일 | 규칙 |
|---|---|
| 보낼 문서를 만들면 | `_발신함/<YYYY-MM-DD>_<받는 곳>_<내용>/`에 두고 `_발신함/목록.md`에 상태 "초안"으로 적는다. 보낼 문서는 커밋해도 되지만 **`목록.md`는 로컬 전용이라 커밋하지 않는다**(2026-11-09). 목록에도 공용 저장소에 들어가는 문서에도 개인 노트 위치와 절대 경로를 쓰지 않는다 |
| 🔴 발송 전이어도 저장한다 | "발송 전"은 상태 표시일 뿐 저장하지 말라는 뜻이 아니다. 보낼 문서도 처음부터 `_발신함/`에 만든다. 산출물 위치는 [[00 세션 공통 지침]] §15 |
| 보고할 때 | 발송 전 문서가 있으면 **"보내셨나요? 언제, 어디로 보내셨나요?"를 반드시 묻는다** |
| 사용자가 보냈다고 하면 | 그때 "발송됨"으로 바꾸고 날짜, 채널, 사용자 답변을 적는다. 이때부터 "회신 대기"라고 쓸 수 있다 |
| 다른 문서에 적을 때 | 목록의 상태 그대로 쓴다. 발송 확인 전이면 "작성 완료(발송 전)" |

## 1. 상태

| 상태 | 뜻 | 바꾸는 사람과 근거 |
|---|---|---|
| 초안 | Claude가 만들었고 사용자가 아직 보지 않음 | Claude가 만들 때 |
| 검토 요청 | 사용자에게 보여 주고 고칠 곳이나 발송 여부를 묻는 중 | Claude가 보고할 때 |
| 발송됨 | **사용자가 직접 보냈다고 말함** | 사용자의 말. 날짜, 채널(카톡, 메일 등), 사용자 답변을 적는다 |
| 회신 받음 | 받는 쪽의 답이 왔음 | 사용자가 넘긴 회신 자료(`_수신함/`)나 사용자의 말 |
| 보류 | 사용자가 보내지 않기로 했거나 미룸 | 사용자의 말 |
| 종료 | 회신을 반영해 일이 끝남 | 반영한 작업 |

🔴 **"발송됨"은 사용자의 말로만 바뀐다.** 문서를 만들었다, 사용자에게 보여 줬다, 사용자가 "좋네"라고 했다는 것은 발송이 아니다. 애매하면 묻는다.

## 2. 폴더와 목록

```
<프로젝트 저장소 루트>/
└─ _발신함/
   ├─ 목록.md                                    보낼 문서와 상태
   ├─ 2026-11-06_발주사_확인요청_10건/
   │   └─ 확인요청서.md (또는 .docx, .pdf)
   └─ 2026-11-06_디자이너_아이콘_요청/
```

- **폴더 이름:** `YYYY-MM-DD_<받는 곳>_<내용>`. 날짜는 만든 날이다. 받는 곳은 `발주사`, `고객`, `디자이너`, `기획`, `서버팀`, `동료`처럼 역할로 쓴다.
- **여러 저장소로 나뉜 프로젝트**는 문서를 모아 두는 저장소의 `_발신함/`을 쓴다. 받은 자료의 `_수신함/`과 같은 저장소다.
- **목록.md** 형식:
  ```
  | 만든 날 | 받는 곳 | 내용 | 폴더 | 상태 | 발송 확인 (날짜, 채널, 사용자 답변) | 회신 |
  |---|---|---|---|---|---|---|
  | 2026-11-06 | 발주사 | 확인 요청 10건 | `2026-11-06_발주사_확인요청_10건/` | 검토 요청 | | |
  | 2026-11-03 | 디자이너 | 아이콘 요청 | `2026-11-03_디자이너_아이콘_요청/` | 발송됨 | 2026-11-04, 카톡, "아까 보냈어" | |
  ```
- 문서를 고치면 같은 폴더에서 고치고, 이미 보낸 판은 이름 뒤에 `_발송본`을 붙여 남긴다.

## 3. 🔴 보고할 때 반드시 묻는다

작업 보고 끝에, 발송 전(초안, 검토 요청) 문서가 하나라도 있으면 목록으로 보여 주고 묻는다.

```
보낼 문서 중 발송 확인이 안 된 것이 있습니다.
- 발주사 확인 요청 10건 (11.06 작성)
- 디자이너 아이콘 요청 (11.03 작성)
보내셨나요? 보내셨다면 언제, 어디로(카톡, 메일 등) 보내셨는지 알려 주세요. 아직이면 그대로 "작성 완료(발송 전)"로 두겠습니다.
```

- 답을 받기 전에는 "회신 대기", "전달함", "보냈음", "요청드렸음"으로 쓰지 않는다.
- 사용자가 답을 건너뛰면 다음 보고에서 다시 묻는다. 세션이 바뀌면 시작할 때 묻는다(세션 시작 훅이 알려 준다).

## 4. 다른 문서에 적을 때

주간목표, 날짜별 노트, 인계 문서, 진척표, 주간보고, 트래커, 다른 세션에 넘기는 글 모두 같다.

| 상태 | 쓰는 말 | 쓰지 않는 말 |
|---|---|---|
| 초안, 검토 요청 | "확인 요청서 작성 완료(발송 전)" | 전달함, 발송함, 보냄, 요청드림, 회신 대기, 답변 대기 |
| 발송됨 | "확인 요청서 발송(11.04, 카톡), 회신 대기" | |
| 보류 | "확인 요청서 작성, 발송 보류" | |

- 예외: 주간보고는 고객이 읽는 문서라 발송 전 문서를 "작성 완료, 전달 준비"로 쓴다([[11 주간보고 검수]] 2장 14번). 이 밖에는 "작성 완료(발송 전)" 하나만 쓴다.
- 다른 세션에 "회신을 기다리는 중"이라고 알리기 전에 목록의 상태를 본다.

## 5. 지키는 장치

- **문서 쓰기 훅:** 문서에 "전달함", "발송함", "회신 대기", "보냈습니다" 같은 발송 표현을 쓰려 하면, 사용자 확인이 있었는지 다시 보라고 Claude에게 알린다(막지는 않는다).
- **세션 시작 훅:** 그 프로젝트 문서 저장소의 `_발신함/목록.md`에 초안이나 검토 요청 상태의 문서가 있으면, 사용자에게 보냈는지 물어보라고 알린다.
- 자세한 동작은 [[10 자동 장치]].
