> 이 문서는 피그마 컴포넌트를 **어떻게 만드는지**(개념, 속성, 이름)와 피그마 MCP 작업 메모를 다룬다.
> 피그마 디자인 규칙의 **원본은 [[16 디자인 시작 체크리스트]]**다. 받을 자료, 기초 요소와 컴포넌트 목록, 상태 화면, 작업 순서, 점검표는 그쪽에 있다.
> 화면 하나를 레퍼런스로 다시 그리는 일은 [[디자인 레퍼런스 지침]]을 함께 읽는다.

## 0. 한 줄 요약

**화면부터 그리지 않는다.** 색과 글자와 간격을 변수로 먼저 정하고, 그 변수만 써서 컴포넌트를 만들고, 컴포넌트를 조립해서 화면을 만든다. 화면에 숫자나 색을 직접 넣었다면 기준을 건너뛴 것이다.

---

## 1. 디자인 시스템이 담는 것

디자인 시스템은 디자인 원칙, 기초 스타일, 재사용 컴포넌트, 사용 흐름 패턴, 코드와 맞춘 토큰을 하나의 기준으로 모은 것이다. 서비스 전체에서 화면이 같은 규칙으로 보이게 하고, 매번 새로 그리지 않고 조립하게 하며, 색이나 글자를 바꿀 때 원본 한 곳만 고치면 되게 하려고 만든다.

| 층 | 담는 것 |
|---|---|
| 원칙 | 브랜드가 지키려는 방향과, 둘 중 하나를 고를 때의 판단 기준 |
| 기초 요소 (Foundations) | 색, 글자, 레이아웃과 격자, 간격, 아이콘, 둥글기와 그림자, 움직임 |
| 컴포넌트 (Components) | 입력과 선택, 탐색, 정보 표시, 알림과 겹침 화면 |
| 패턴과 운영 기준 | 사용 흐름, 화면 문구 규칙, 접근성, 디자인 토큰 이름 규칙 |

참고할 만한 공개 시스템은 KRDS(행정안전부와 한국지능정보사회진흥원의 범정부 디지털 서비스 디자인 시스템), 토스 TDS, Google Material Design, Apple Human Interface Guidelines, 우아한형제들 우아한공방이다. 구조를 참고할 뿐, 색이나 모양을 가져오지 않는다.

## 5. 피그마 컴포넌트 규칙

출처: 피그마 고객센터 "Figma 컴포넌트 가이드"와 "컴포넌트 속성 생성 및 사용" (2026-11-12 확인).

### 5-1. 기본 개념

- **기본 컴포넌트(메인)**는 원본이고, **인스턴스**는 원본에 연결된 사본이다. 원본을 고치면 모든 인스턴스가 따라 바뀐다.
- 같은 부품의 크기, 상태, 색 차이는 **변형(Variant)**으로 한 묶음(컴포넌트 세트)에 모은다. 구조가 다르면 따로 만든다.
- 인스턴스에서 글자나 색을 바꾸는 것(오버라이드)은 허용하지만, **인스턴스를 분리(Detach)하지 않는다.** 분리하면 원본과 끊겨 기준이 깨진다. 분리해야만 될 것 같으면 원본에 변형이나 속성을 더한다.

### 5-2. 속성 네 가지

| 속성 | 쓰는 곳 | 주의 |
|---|---|---|
| 변형 속성 | 상태, 크기, 종류 | 컴포넌트 세트 안에서만 만든다. 유일한 변형을 지우면 세트 전체가 지워진다 |
| 불리언 속성 | 아이콘이나 배지처럼 켜고 끄는 레이어 | 프로토타입 연결이 걸린 레이어에는 쓰지 않는다 |
| 텍스트 속성 | 단추 문구, 제목처럼 바꿔 쓰는 글자 | 서식 있는 글자(글머리, 위첨자)는 안 된다 |
| 인스턴스 교체 속성 | 안에 든 아이콘이나 작은 부품 갈아 끼우기 | 선호 값(Preferred values)에 어울리는 것만 골라 둔다 |

- 기본값을 바르게 둔다. 새 인스턴스를 놓자마자 맞는 모양이어야 한다.
- 안쪽 인스턴스의 속성은 노출(Expose nested instances)해서 바깥에서 한 번에 고치게 한다.
- 컴포넌트 설명 칸에 용도, 쓰지 말아야 할 곳, 접근성 요구(스크린 리더 이름 등)를 적는다.

### 5-3. 이름과 정리

- 이름은 하는 일로 짓는다([[디자인 레퍼런스 지침]] 2-4). 형식은 `분류/이름`이다(예: `Input/Button`, `Input/Search`, `Card/Product`, `Nav/Header`). 자세한 목록은 [[16 디자인 시작 체크리스트]] 4-1.
- 변형 속성 이름과 값은 영어 소문자 또는 정해진 한 가지 표기로 통일한다(예: `state=default`, `size=md`).
- 다른 컴포넌트 안에서만 쓰는 안 보이는 부품은 이름 앞에 `_`를 붙여 게시 목록에서 숨긴다(예: `Nav/_Bottom Nav Item`).
- 페이지 구성은 [[16 디자인 시작 체크리스트]] 2-2를 따른다. 화면은 기기 폭별로 프레임을 맞춘다.
- 다른 파일에서도 쓰려면 팀 라이브러리로 게시한다. 게시는 사용자가 확인한 뒤에 한다.

## 8. 피그마 MCP로 만들 때 (작업 메모)

- use_figma를 부르기 전에 figma-use 스킬을 먼저 읽는다.
- 파일 작업 전에 세션을 먼저 만들고(create_session), 그 세션 번호를 이후 호출에 함께 넘긴다.
- use_figma는 한 번에 하나씩 차례로 부른다. 앞 단계에서 만든 노드 ID를 돌려받아 다음 단계에 쓴다.
- 색 값은 0부터 1 사이 숫자로 넣는다(예: #0074E0은 r 0, g 0.455, b 0.878).
- 글자를 넣기 전에 글꼴을 먼저 불러온다. 고객 BI의 글꼴이 없으면 대체 글꼴을 쓰고 그 사실을 보고한다.
- 단계마다 스크린샷으로 확인한다. 만든 노드 ID는 프로젝트 `_작업/figma/`의 메모 파일에 적어 두고, 대화가 압축되어도 이어서 작업할 수 있게 한다.
- 실행 하나가 오류로 멈추면 그 실행의 변경은 모두 취소된다. 고쳐서 같은 내용을 다시 실행하면 된다.
- 자동 레이아웃 프레임을 `resize()`하면 높이가 고정으로 바뀐다. 내용에 맞출 프레임은 마지막에 `layoutSizingVertical = 'HUG'`를 다시 준다.
- 인스턴스 안에는 자식을 넣을 수 없다. 인스턴스마다 달라지는 부분은 컴포넌트 속성(글자, 켜고 끄기, 바꿔 끼우기)으로 미리 열어 둔다.
- 인스턴스 교체 속성으로 아이콘을 바꾸면 아이콘 색 덮어쓰기가 풀린다. 바꾼 뒤 색을 다시 지정한다.
- 피그마는 한글을 글자 단위로 줄바꿈한다. 상품명처럼 줄이 바뀌는 글은 컴포넌트 설명에 개발 메모(`word-break: keep-all`)를 적고, 시안에서 눈에 띄는 곳만 줄바꿈을 직접 넣는다.
- 다 만든 뒤에는 처음 보는 검수자(서브에이전트)에게 [[16 디자인 시작 체크리스트]] 11장 점검표와 고객 원문 대조를 맡긴다. 검수자는 고치지 않고 읽기만 한다.
