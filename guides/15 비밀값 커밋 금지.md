# 비밀값 커밋 금지

> **키, 토큰, 비밀번호, 인증서, 개인 키는 어떤 경우에도 커밋하지도 푸시하지도 않는다.**
> 한 번 원격에 올라간 값은 지워도 이력에 남는다. 그때 할 수 있는 일은 **재발급**뿐이다(3장).
> 비밀값 규칙은 이 문서가 원본이다. 다른 지침서는 한 줄 요약과 이 문서 링크만 둔다.

관련 문서: [[12 받은 자료 정리]] (`_수신함/_비밀/`), [[10 자동 장치]]

---

## 한눈에 보기

| 무엇 | 규칙 |
|---|---|
| 비밀값을 두는 곳 | `.env`(gitignore), 비밀 관리 도구, 받은 키 파일은 `_수신함/_비밀/`(gitignore) |
| 코드와 설정에 쓰는 법 | 환경 변수 이름이나 자리 표시만 쓴다(`process.env.API_KEY`, `${DB_PASSWORD}`, `<발급받은 키>`) |
| 예시 파일 | `.env.example`처럼 이름 끝에 `.example`을 붙이고 값은 비운다 |
| 걸렸을 때 | 값을 지우고 옮긴다. 이미 새어 나갔으면 **먼저 재발급**을 요청하고, 그다음 파일과 이력을 정리한다(3장) |
| 문서에 적을 때와 커밋 전 | 라벨만 남기고 값은 가린다. 비밀 자료가 든 폴더에서는 경로를 지정해 add하고, 커밋 전에 한 번 더 찾아본다(6장) |
| 진짜 비밀값이 아닌데 걸렸을 때 | 사용자에게 알린다. 허용 목록은 **사용자만** 고친다 |
| 검사를 끄는 것 | **어떤 경우에도 하지 않는다.** `--no-verify`, 훅 경로 바꾸기, 허용 목록 고치기 모두 Claude는 하지 않는다 |

## 1. 비밀값으로 보는 것

**값의 모양으로 찾는 것**

| 종류 | 예 |
|---|---|
| 클라우드와 개발 도구 키 | AWS 액세스 키, Google API 키, GitHub와 GitLab 토큰, Slack 토큰, npm 토큰, AI 서비스 키 |
| 결제 키 | 결제 대행사의 운영 키와 시험 키(시험 키도 커밋하지 않는다) |
| 인증 토큰 | JWT, 액세스 토큰, 리프레시 토큰 |
| 개인 키 | `BEGIN … PRIVATE KEY` 블록, 서비스 계정 JSON 안의 `private_key` |
| 접속 문자열 | 비밀번호가 들어간 DB 주소(`postgres://계정:비밀번호@…`) |
| 비밀값 대입 | `secret`, `password`, `api_key`, `token`, `client_secret`, `..._KEY` 같은 이름에 실제 값을 넣은 줄. 안드로이드 서명 비밀번호(`storePassword`)도 여기에 든다 |

**파일 이름만으로 막는 것**

`.env`(`.env.example` 등 예시 파일은 허용), 서비스 계정과 `*adminsdk*.json`, `credentials.json`, `client_secret*.json`, `*.tfvars`, `*.tfstate`, `*.pem`, `*.p8`, `*.p12`, `*.pfx`, `*.key`, `*.keystore`, `*.jks`, `*.mobileprovision`, `google-services.json`, `GoogleService-Info.plist`, `key.properties`, `keystore.properties`, SSH 개인 키(`id_rsa`, `id_ed25519` 등. `.pub`는 허용), `.npmrc`, `.pypirc`, `.netrc`, `.htpasswd`, `_비밀/` 아래 모든 파일

**비밀값으로 보지 않는 것(통과)**

환경 변수를 읽는 코드(`process.env.X`, `os.environ`), 자리 표시(`${X}`, `<…>`, `your-…`, `xxx`, `change-me`), 공개 키(`.pub`), 비밀번호라는 낱말만 있는 화면 문구

## 2. 🔴 엣지 상황과 막는 방법

| 상황 | 막는 방법 |
|---|---|
| 사용자가 터미널, IDE, 다른 도구에서 직접 커밋하거나 푸시함 | **git 전역 훅**(이 사용자의 모든 저장소)이 커밋 직전과 푸시 직전에 검사한다 |
| `git commit -a`, `git commit <파일>`처럼 스테이징 없이 커밋함 | 작업 폴더의 바뀐 내용까지 검사한다 |
| 키를 넣은 커밋을 만들고 다음 커밋에서 지운 뒤 푸시함 | 푸시할 때 원격에 없는 **모든 커밋의 이력 전체**를 검사한다. 지운 것도 이력에 있으면 막는다 |
| `--no-verify`로 커밋 검사를 건너뛰고 나중에 푸시함 | 푸시 검사에서 이력을 다시 보고 막는다 |
| 새 브랜치 첫 푸시, `--all`, `--tags`, 강제 푸시 | 원격에 아직 없는 커밋을 모두 검사한다 |
| `git -c 설정=값 commit`, `git -C 경로 commit`처럼 옵션을 앞에 붙임 | Claude 훅이 옵션을 건너뛰고 커밋으로 알아본다 |
| `git add -f`로 gitignore된 `.env`나 `_비밀/`을 강제로 넣음 | 파일 이름으로 막는다 |
| 커밋 메시지나 PR 본문, 이슈, 릴리스 글에 키를 붙여 넣음 | 메시지와 본문도 검사한다 |
| `--no-verify`, `git commit -n`, `core.hooksPath` 바꾸기, 허용 목록이나 git 전역 훅 고치기 | Claude는 하지 못하게 막는다 |
| 키 파일 이름을 바꾸거나 다른 확장자로 저장함 | 내용(값의 모양)으로 찾는다 |
| 키가 든 압축 파일(zip, tar, 7z, rar)을 커밋함 | 커밋과 푸시 직전에 압축 파일을 열어 안의 파일 이름과 내용을 검사한다. 받은 자료와 보낼 문서의 압축 파일(`_수신함/`, `_발신함/` 아래)은 내용과 상관없이 막는다(2026-11-09) |
| 저장소 안의 기존 훅(비밀값 점검, 금지어 검사, Git LFS) | 전역 훅이 검사한 뒤 그 저장소의 원래 훅을 그대로 이어서 실행한다 |

## 3. 걸렸을 때

### 3-1. 아직 원격에 나가지 않았을 때

1. 값을 지우고 `.env`나 비밀 관리 도구로 옮긴다. 코드에는 환경 변수 이름만 남긴다.
2. 이미 커밋했으면 그 커밋에서 값을 빼고 다시 커밋한다. 푸시 전이면 원격에는 아무것도 나가지 않았다.

### 3-2. 🔴 이미 새어 나갔을 때

원격에 올라간 값과, 메신저나 메일로 평문으로 받은 값이 여기에 든다. **메신저나 메일로 평문으로 받은 키는 이미 노출된 것으로 취급한다.**

1. **먼저 그 키를 재발급(옛 값 무효화)하도록 사용자에게 알린다.** 지워도 이력에 남고, 지운 커밋의 diff에도 값이 다시 찍힌다. 재발급이 유일한 실질 조치다.
2. 그다음 파일을 정리한다. 값을 빼고 3-1대로 다시 커밋한다.
3. 이력을 다시 쓰는 일(강제 푸시)은 사용자가 정한다.

#### 사례

**한 번 새어 나갔다.** 메신저 대화 내보내기를 받은 자료 폴더(`_수신함/`)에 그대로 커밋했더니 그 안의 키가 함께 올라갔다. 받은 자료는 [[12 받은 자료 정리]] 2장 3번대로 두 번 확인하고 가린 뒤에 넣는다.

### 3-3. 진짜 비밀값이 아닐 때

시험용 가짜 값이나 공개된 예시 값이면 사용자에게 알린다. 사용자가 `~/.claude/harness/secret-allow.txt`에 그 줄을 가리키는 정규식을 넣는다.

## 4. 시험 코드에 가짜 키가 필요할 때

시험 파일에 키 모양 글자를 그대로 쓰면 그 시험 파일이 커밋되지 않는다. **조각으로 나눠 실행할 때 이어 붙인다**(예: `"ghp_" "0123…" "…"`를 이어 붙이는 함수). 이어 붙인 조각 어느 것도 키 모양이 되지 않게 짧게 자른다.

## 5. 지키는 장치

- **git 전역 훅:** `git config --global core.hooksPath`로 켠다. 커밋 직전(내용, 메시지)과 푸시 직전(원격에 없는 이력 전체)에 검사한다. 저장소가 자기 훅 경로(`core.hooksPath`)를 따로 쓰면 그 저장소에서는 돌지 않는다. 설치할 때 그런 저장소를 알려 준다.
- **Claude 훅:** Claude가 실행하는 커밋, 푸시, PR, 이슈 명령을 같은 검사기로 검사하고, 검사를 끄는 명령을 막는다.
- **사용자는 여전히 직접 우회할 수 있다**(`--no-verify`). 이 장치는 실수를 막는 것이다. 가장 확실한 마지막 방어선은 원격 서버의 비밀값 탐지(push protection)이며, 쓸 수 있으면 함께 켜는 것을 권한다.
- 자세한 동작과 끄는 법은 [[10 자동 장치]].

## 6. 문서에 적을 때와 커밋 전에

- 문서에 적어야 하면 **라벨만 남기고 값은 가린다.**
  ```
  외부 로그인 Client Secret: [가림, 실제 값은 .env나 비밀 관리 도구에만]
  ```
- 비밀 자료가 들 수 있는 폴더(받은 자료, 작업 문서, 메신저 내보내기)에서는 `git add -A`나 `git add .`를 쓰지 않는다. 경로를 하나씩 적는다.
- 커밋 전에 한 번 더 찾아본다.
  ```bash
  git diff --cached | grep -nEi "secret|api ?key|password|token" | head
  ```
