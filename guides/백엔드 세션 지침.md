# 백엔드 세션 지침

> 이 문서는 세션을 나누는 기준이 아니라 서버와 DB, 계약을 건드릴 때 펴는 참고 자료다(자세한 규칙: [[03 코딩 규칙]] §8).
>
> 먼저 [[00 세션 공통 지침]]을 읽는다. 여기는 **서버 고유의 것**만 적는다.

---

## 1. 🔴 표만 만들고 쓰는 코드를 안 붙이면, 없는 것보다 나쁘다

자리를 만들었으면 읽는 쪽과 쓰는 쪽을 같은 커밋에 붙인다. 서버에서 같은 실수를 두 번 했다(실패 기록 테이블에 INSERT가 없었고, 확정 집계에 읽는 쪽이 없었다). 자세한 규칙과 사례: [[00 세션 공통 지침]] §5.

## 2. 🔴 명세를 그대로 믿으면 구멍이 남는다

명세가 시킨 것을 확인하는 데서 멈추지 말고 **상태 게이트**(비활성, 미승인 리소스로 쓰기가 되는가), 권한 경계, 전제 조건을 함께 점검한다. 승인도 안 난 이벤트가 진짜 보상을 주던 사례: [[기획 세션 지침]] §6.

## 3. 동시성은 코드로 풀지 말고 구조로 막는다

경쟁 조건은 테스트에서 늦게 발견되고, 그때는 일정이 없다.

- **원자 연산 하나로 승부를 낸다**: DB `UNIQUE`와 조건부 `UPDATE ... WHERE`, 또는 Redis `INCR` 반환값 비교.
  둘 다 "먼저 잡은 쪽이 이긴다"라 자연스럽게 **정확히 1명**이 된다.
- "누가 진짜 N번째냐"를 정렬이나 타임스탬프로 가리려 들지 않는다. **밀리초 경쟁이라 공정성 차이가 없다.**
- **유실 0이 필요하면 비동기 배치 이전에 동기로 durable 기록**한다. 그 원자 연산 지점이 곧 기록 지점이다.
- 착수 **전에** 정책을 확정하고 시작한다. 코드로만 풀려다 나중에 발견하면 일정을 넘긴다.

## 4. 마이그레이션

- **적용된 마이그레이션은 개명하거나 수정하지 않는다.** 마이그레이션 테이블이 **이름과 체크섬**을 들고 있다.
  `migration.sql` 안 **주석 한 글자만 바뀌어도** "적용 후 변경됨"으로 막힌다.
- 그래서 문서 번호를 재번호해도 **마이그레이션 폴더 이름은 옛 번호 그대로 둔다.** 버그가 아니다.
  대신 **어긋난다는 사실을 인계 문서에 적는다.**
- 스키마를 고쳤으면 **ORM 클라이언트 재생성 후 재시작**. 안 하면 앱이 아예 안 뜨고,
  에러 메시지가 원인을 안 가리켜서 시간을 먹는다.

## 5. 파괴적 스위치는 기본 꺼짐과 승인

> 데이터 파기 배치가 **기본 꺼짐**으로 돌고 있었다. 켜면 되돌릴 수 없다.
> 켜기 전 조건이 둘이었는데 하나(굳힌 값을 읽는 코드)를 **안 닫고 켰으면 지난 이벤트가 전부 "참여자 0명"** 이 될 뻔했다.

- 켜는 조건을 **명시적으로 목록화**하고, 각각이 닫혔는지 표로 관리한다.
- 클라이언트 승인이 조건이면 **승인 없이 켜지 않는다.**
- 킬스위치를 같이 만든다. 사고 시 즉시 끌 수 있어야 한다.
- 파기 대상이 **누락되지 않았는지** 본다. 한 축이 다른 축에 매달려 있지 않으면 별도 배치가 필요하다.

## 6. 시간대와 날짜 경계

날짜와 시간대는 [[06 한국 시간 처리 모듈]]로만 다룬다(한국 자정의 UTC 시각을 잘라 하루 전 날짜가 된 사례도 06 §2에 있다). 이걸 고친 뒤 테스트 기대값 쪽이 틀려 있던 일도 있었다. 테스트가 빨갛다고 코드부터 고치지 않는다(자세한 규칙: [[03 코딩 규칙]] §5).

## 7. 환경과 컨테이너 함정

- **`docker compose restart`는 `.env`를 다시 읽지 않는다.** 반드시 `up -d`.
  (환경변수가 컨테이너 안에 없어서 한참 헤맸다.)
- 필수 키가 없을 때 **던지지 말고 해당 기능만 끄고 부팅 error 로그를 남긴다.**
  던지면 서비스가 통째로 죽는다. 그 로그 덕에 위 문제를 잡았다.
- **테스트를 조용히 가르는 오버라이드**를 조심한다. `.env` 값에 따라 통과와 실패가 뒤집히는 테스트가 있었다.
  절대값 대신 **비율이나 상대 조건**으로 쓰면 값과 무관해진다.
- 라이브러리 **버전 핀에는 이유가 있다.** 올리기 전에 왜 박혔는지 확인한다(ESM 전용 전환 등).

## 8. 배포 전 되돌릴 것

테스트 편의로 넣은 값은 **그대로 나가면 안 된다.** 목록으로 관리한다.

```
[ ] 시간 단축 오버라이드 (.env)
[ ] 테스트용으로 넓힌 경계값과 버퍼
[ ] 테스트용으로 늘린 지급량과 수량
[ ] 개인, 임시 API 키를 운영 키로 교체
[ ] 서버 시드 데이터 정리 (아래)
```

### 서버 시드 데이터

> 테스트 계정에 결과 데이터를 4건씩 넣어 상태를 전부 덮었다. 그런데 **실제 데이터가 섞여 있어** 통째로 지우면 안 됐다.

```sql
-- 시드만 골라내는 기준을 인계 문서에 적는다 (생성 시각 등)
```

- 시드와 목데이터는 **식별 가능하게** 만든다. 나중에 골라낼 수 없으면 못 지운다.
- 실데이터와 섞이는 환경이면 **넣기 전에 지우는 방법을 정한다.**

이름이 비슷한 남의 담당 키를 건드리지 않는 규칙은 [[앱 세션 지침]] §10에 있다.

## 9. 앱 및 웹과의 배포 순서

이 절이 배포 순서의 원본이다. **순서를 틀리면 구멍이 생긴다.**

1. 서버 거절 로직 배포
2. 앱이 플래그 전송 시작
3. 앱이 로컬 차단 제거 (3을 2보다 먼저 하면 서버가 아직 안 막는 무방비 구간이 생긴다)

- 반대로 앱이 안 보내는 값을 서버가 그냥 덮어쓰면 **구버전 앱이 켤 때마다 수집값이 비워진다**. **보낸 것만 덮도록** 한다.
- 앱이 로컬에서 먼저 막고 있으면 **서버에 요청이 안 와서 기록이 안 쌓인다.** "부정 시도를 기록으로 남기라"는 요구가 있으면 이 구조부터 바꾼다.
- 앱은 **구버전이 오래 남는다.** 서버는 항상 구버전 앱을 견뎌야 하고, 앱은 **없는 필드에 관대**해야 한다.

## 10. 클라이언트가 보내는 값은 주장이지 근거가 아니다

기기 판정(모의위치, 루팅 등)은 **앱이 자기에 대해 하는 주장**이다.
앱을 뜯어 항상 거짓으로 보내면 그만이라 **신뢰의 근거로 삼지 않는다.**

- 진짜 방어선은 **서버가 가진 것**이다(재검증, 속도와 빈도 제한).
- 이 값은 **무심코 하는 부정을 돌려세우고 기록에 남기는 층**이다. 그렇게 명세에 적는다.
- **기본값은 통과**여야 한다. 안 보내는 구버전 앱이 전부 막히면 안 된다.
- 서버가 이미 아는 것(IP, 접속시각)은 **앱에게 묻지 않는다.**
- 자주 안 바뀌는 값(기기모델, OS)은 **기기 등록에 두고** 매 요청에 싣지 않는다.

## 인계 문서에 꼭 담을 것

공통 항목(가장 크게 당한 것과 재현 방법, 남에게 물어 놓은 것, 안 하기로 한 것과 이유, 확인하지 못한 것 등)은 [[00 세션 공통 지침]] §8을 따른다. 서버에서 더 담을 것:

```
[ ] 배포 전 되돌려야 하는 임시값 목록          (§8)
[ ] 서버 시드 데이터 위치와 지우는 기준        (§8)
[ ] 파괴적 스위치의 상태와 켜기 조건            (§5)
[ ] 푸시 안 한 커밋 (작업 브랜치는 바로 푸시)
[ ] 보호 브랜치로 합칠 커밋과 승인 상태
[ ] 하지 않아도 되는 것 (확인 완료. 다음 세션의 재조사를 막는다)
[ ] 테스트, lint, 미러 상태와 그 숫자가 실제로 무엇을 덮는지
```
