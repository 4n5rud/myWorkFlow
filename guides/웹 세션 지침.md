# 웹 세션 지침

> 관리자 웹 기준이다. §4~§7과 §9는 손님용 웹을 포함한 모든 웹에 해당한다.
>
> 이 문서는 세션을 나누는 기준이 아니라 웹 화면을 건드릴 때 펴는 참고 자료다(자세한 규칙: [[03 코딩 규칙]] §8).
>
> 먼저 [[00 세션 공통 지침]]을 읽는다. 여기는 **운영 웹 고유의 것**만 적는다.
> 운영 화면의 사용자는 **일하는 사람**이다. 예쁜 것보다 **틀리지 않는 것**이 먼저다.

---

## 1. 🔴 화면이 사실과 다른 인상을 주지 않는다

> 운영자가 넣은 비율의 **합과 실제로 적용되는 비율이 달랐다.**
>
> ```
> 입력   H 15%, I 25%, J 40%     합 80%
> 실제   H 15.0%, I 21.3%, J 25.5%   합계 61.75%
> ```
>
> 서버가 항목을 차례로 훑으며 **처음 걸린 하나**만 고르기 때문이다. 뒤 항목은 앞이 전부 빗나가야 기회가 온다.

**가드가 없는 것과는 다른 문제다.** 값은 저장되고 동작도 의도대로인데,
**화면이 운영자에게 거짓 인상**을 준다. 그래서 그래프는 **입력값이 아니라 실효값**으로 그린다.

- 운영자가 넣은 숫자와 **시스템이 실제로 하는 일**이 다르면, 다른 쪽을 보여준다.
- 막지는 않는다. 의도적으로 그렇게 쓰는 경우가 있다. **경고하고 저장은 되게** 한다.
- 일괄 보정 버튼 같은 건 신중하게. **버튼 하나가 여럿을 덮어쓰고 중간에 실패하면 절반만 바뀐다.**

## 2. 🔴 숫자 둘이 나란히 있으면 같은 것을 세는지 본다

> 대시보드 머리 숫자와 그래프가 **서로 다른 기간**을 세고 있었다.
> 안 맞으면 문의가 오는 게 아니라 **신뢰를 잃는다.**

- 합계가 전체보다 클 수 있는 구조(중복 집계)라면 **화면에 그대로 적는다.**
  > *"날짜별 이용자는 그날 방문한 사람 수예요. 여러 날 오신 분이 있어 합계가 전체보다 클 수 있어요."*
- 설명 없이 두면 운영자가 **버그로 신고**하거나, 더 나쁘게는 **잘못된 보고서를 만든다.**

## 3. 마스킹과 가공 규칙을 클라이언트가 갖지 않는다

> 서버가 마스킹된 문자열을 준다. **어드민은 그걸 그대로 그린다.**
> 규칙이 두 곳에 생기면 한쪽이 낡으면서 **주소가 새는 날이 온다.**

- **가려야 하는 축은 "누구의 데이터냐"가 아니라 "누가 보느냐"** 다. 본인에게는 전문을 준다.
- 원문 열람은 **별도 엔드포인트와 감사 로그**로. 열람 전 **고지 다이얼로그**를 띄운다.
  > *"열람 기록이 남아요"*
- 필드명이 그대로이고 **값만 마스킹돼 오는** 경우가 있다. 타입이 안 바뀌니 조용히 지나간다. 계약을 확인한다.
- 원문이 필요한 화면(송장 등록 등)에 **주소 블록이 없으면 담당자가 딴 데서 찾아온다.**
  그 진입이 곧 열람이므로 **거기에 붙인다.**

## 4. 경계값을 반드시 따로 돌려 본다

> `every`는 **빈 배열에 `true`** 다. 슬롯이 0개일 때 소진 예측이 *"1명째에 다 떨어져요"* 라고 말했다.

- 0건, 1건, 상한 초과를 각각 넣어 본다.
- 예측이나 시뮬레이션을 만들었으면 **다른 방법으로 검산**한다.
  (기댓값 계산을 몬테카를로 400회와 대조해 1% 내 일치를 확인한 사례가 있다.)

## 5. 아무도 안 열어 본 화면이 있다

> `ready` 상태 데이터가 0건이라 **송장 등록 다이얼로그를 아무도 열어 본 적이 없었다.**

- 상태별로 **데이터가 0건인 화면**을 찾아 목록으로 만든다. 거기가 미검증 구간이다.
- 붙이면서 **그 흐름을 한 번 돌려 본다.** 시드 데이터를 만들어서라도.

## 6. 코드만 읽어서는 안 잡히는 버그가 있다

먼저 QA 스킬(4n5rud-qa)과 브라우저로 화면을 직접 열어 확인한다. 브라우저를 쓸 수 없을 때는 curl로 검증하는 방법이 대안이다.

```bash
# 대안: 백엔드에 curl 로그인, 세션 쿠키 확보, 페이지를 받아 SSR 결과 검증
```

- 시드 계정의 비밀번호는 **시드 파일에서 확인**한다(값은 문서에 적지 않는다).
- 로그인 요청 **필드명이 예상과 다른** 경우가 많다. 계약을 본다.
- 실제로 코드만 읽어서는 안 잡히는 버그를 이렇게 화면을 받아 보고 잡았다.

## 7. 폼이 없는 단계에 저장 버튼을 두지 않는다

> 다이얼로그가 즉시 저장하는 단계에 저장 버튼을 뒀더니,
> 눌러도 아무 일이 없고 토스트도 안 떠서 **저장이 안 된 것으로 읽혔다.**

- 버튼은 **할 일이 있을 때만** 둔다.
- 반대로 **할 일이 있는데 피드백이 없는 것**도 같은 죄다. 성공도 실패도 말해 준다.

## 8. 운영 UI에 백엔드 내부를 노출하지 않는다

- 큐, 배치, 캐시, 인덱스 조작 위젯을 화면에 두지 않는다. **집계 결과만** 보여준다.
- 서버 건강성은 화면이 아니라 **알림 채널**로 다룬다.
- 읽기 전용 통계에 **버튼 어포던스를 주지 않는다.** 누를 수 있을 것처럼 생기면 누른다.
- 조건부 요소는 **노출 조건을 명시**한다. 상시인지 조건부인지가 명세에 없으면 구현이 갈린다.

## 9. 프레임워크 함정

- **React Compiler는 렌더 중 변수 재대입을 막는다.** 누적값은 `let`으로 쌓지 말고
  `slice().reduce()` 같은 방식으로 그때그때 계산한다.
- 포맷 스크립트가 **문서에는 있는데 실제로는 없는** 경우가 있다. 없으면 도구를 직접 부른다.
- 상태를 URL이나 스텝으로 나눌 때 **폼이 없는 단계**를 별도로 취급한다(§7).

## 10. 단계나 마법사를 나눌 때

> 한 단계에 **서로 무관한 두 기계**가 있었다. 하나는 즉시 확률로, 다른 하나는 사후에 쿠폰으로 동작하는데
> **공유하는 건 식별자뿐**이었다. 나누고 나서야 각각에 맞는 경고를 붙일 자리가 생겼다.

- **한 화면에 두 개의 다른 규칙이 있으면 나눈다.** 나누기 전에는 경고를 붙일 자리조차 없다.
- 선택 단계는 **비어 있어도 경고하거나 차단하지 않는다.** 안 쓰는 게 정상인 기능이 있다.
- **빈 상태가 곧 답**이면 별도 플래그를 만들지 않는다. 저장할 것이 늘면 계약, 스키마, 검증이 딸려 온다.

## 인계 문서에 꼭 담을 것

공통 항목(막혀 있는 것, 안 하기로 한 것과 이유, 재현 방법, 확인하지 못한 것 등)은 [[00 세션 공통 지침]] §8을 따른다. 웹에서 더 담을 것:

```
[ ] 🔴 이번에 발견한 "화면이 거짓을 말하던 것"
[ ] 서버가 이미 냈는데 아직 안 붙인 것 (며칠 만에 도착하는 경우가 많다)
[ ] 검증 안 된 화면 (데이터 0건이라 못 열어 본 것 포함)
[ ] 설계안 링크와 아티팩트
```
