# 화면 문구와 장식 덜어내기

> AI가 만든 화면에 흔히 붙는 군더더기(제목 위 꼬리표, 장식 번호, 되풀이하는 부제, 보이는 것을 설명하는 안내 글, 상태와 상관없는 배지와 점, 그래프의 꾸밈)를 찾아 지우는 기준이다. 이 문서를 읽으면 무엇을 지우고 무엇을 남길지, 고친 뒤 어떻게 보고할지 정할 수 있다.

> **출처와 라이선스:** 규칙의 틀과 번호(U1~U20)는 [unslop-ui](https://github.com/felipebasurto/unslop-ui)(Copyright (c) 2026 Felipe Basurto, MIT)에서 왔다. 예시와 단서는 한국어 화면과 우리 작업 규칙에 맞춰 새로 썼다. 계수기 도구(`ui-tells.py`)는 원본 스크립트를 고친 것이고, 파일 머리에 원본 라이선스 전문을 남겼다.

좋은 화면은 읽는 것이 아니라 쓰는 것이다. 사용자가 무엇을 하는 데 필요한 말만 남기고 나머지는 지운다. 문장 자체는 [[05 쇠맛 줄이기]]를, 오류와 빈 상태 문구는 [[20 오류 안내 쓰기]]를, 아이콘 바탕과 디자인 파일 규칙은 [[16 디자인 시작 체크리스트]]를 함께 따른다.

## 가. 먼저 정할 것: 고쳐도 되는 화면인가

| 화면 | 할 일 |
|---|---|
| 이번 작업에서 새로 만든 화면과 목업 | 바로 덜어낸다 |
| 이미 있는 화면(배포됐거나 고객이 확인한 화면) | 고치기 전에 찾은 것을 보고하고 정하게 한다. 기존 화면 동작과 문구를 바꾸는 일이라 범위 밖이면 먼저 묻는다 |
| 고객이 정해 준 문구, 기획서와 화면 설계서에 적힌 문구 | 고치지 않는다. 덜어낼 후보로 보고한다 |
| 고객용 목업(실제 앱과 똑같아야 하는 것) | 실제 앱에 있는 것은 그대로 둔다. 목업에서만 덧붙인 군더더기만 지운다 |

## 나. 원칙

1. **지우기가 먼저다.** 고쳐 쓰라는 규칙(U3, U8, U12)에서도 새 문구에는 화면과 코드에 이미 있는 사실만 쓴다. 제품이 쓰는 이름, 기능 이름, 화면에 묶인 데이터가 그것이다. 코드로 확인할 수 없는 숫자, 속도, 연동, 장점은 쓰지 않는다. 쓸 사실이 없으면 지우거나, 그대로 두고 할 일로 보고한다.
2. **실제 상태 시험.** 배지, 상태 점, 상태 문구는 조건이나 값에 따라 그려질 때만 남긴다(`{isLive && ...}`, `status === "online"`, 서버 응답 값). 늘 같은 글자로 박혀 있으면 장식이다.
3. **접근성은 지운다고 사라지지 않는다.** `aria-label`, `alt`, 아이콘 단추의 이름, 화면 낭독기용 글자는 지우지 않는다. 지운 글자가 그 요소의 유일한 이름이었으면 `aria-label`(Flutter는 `Semantics`의 `label`)로 옮긴다. 입력칸의 보이는 이름표는 자리 표시 글자나 `aria-label`로 바꾸지 않는다.
4. **글자의 출처에서 고친다.** 번역 파일(i18n, ARB), 서버 응답, 고정 데이터에서 오는 글자는 그 파일에서 고치거나 보고한다. 화면 코드에 새 글자를 박아 넣지 않는다.
5. **확인할 수 없는 주장은 건드리지 않는다.** 고객 수, 가동률, 별점, 후기, 고객사 로고는 지우지도 고쳐 쓰지도 않고 할 일로 보고한다.
6. **지운 자리를 치운다.** 요소를 지우면 그 요소만을 위해 있던 빈 감싸개, 자식 하나만 남은 묶음, 여백, 쓰지 않게 된 import와 변수도 지운다.
7. **고칠 게 없는 화면은 그대로 둔다.** "없음"도 결과다.

## 다. 화면 문구 (U1~U8)

| 번호 | 군더더기 | 예 | 할 일 |
|---|---|---|---|
| U1 | 제목 위 꼬리표 | 제목 위의 작은 영문 대문자와 넓은 자간(`OVERVIEW`, `FEATURES`), 점이 붙은 알약(`● 신규 기능`), 목록 위 꼬리표(`POPULAR`) | 지운다. 제목이 이미 구역 이름이다 |
| U2 | 장식 번호 | 순서와 상관없는 `01 02 03`, `01 //`, `§` | 지운다. 사용자가 실제로 따라가는 순서(결제 단계, 설치 단계)면 남긴다 |
| U3 | 습관적인 부제 | "분석" 아래 "데이터를 더 잘 이해하세요", 메뉴 항목마다 붙은 한 줄 설명 | 제목이 말하지 않는 사실을 담을 때만 남긴다. 이름만으로 항목을 구별할 수 없을 때(요금제, 설정)만, 그리고 필요한 항목에만 둔다 |
| U4 | 보이는 것을 설명하는 안내 글 | "아래 버튼을 눌러 시작하세요", "이 카드는 이번 달 매출을 보여 줍니다" | 지운다. 빈 상태, 오류, 지우기 확인은 지우지 않고 "무슨 일이 있었고 무엇을 하면 되는지" 한두 문장으로 고친다. "앗!", "이런!"과 느낌표는 뺀다(20 오류 안내 쓰기) |
| U5 | 화면에 새어 나온 설계 메모 | "(실시간 반영)", "(AI 기반)", 화면이 왜 이렇게 생겼는지 설명하는 글 | 지운다. 사용자가 정말 찾아볼 내용이면 도움말 말풍선으로 옮긴다 |
| U6 | 이어 붙인 상태 줄 | `12개 · 2분 전 수정 · 동기화됨 · v2.1` | 사용자가 보고 움직이는 사실 하나만 남긴다. 나머지는 필요한 자리로 옮기거나 지운다. "동기화됨", "정상 운영 중"처럼 실시간 상태를 말하는 글은 실제 상태 시험을 통과해야 남는다 |
| U7 | 모든 것에 이름 달기 | 이름표, 자리 표시 글자, 안내 글이 모두 "이메일" | 단서 하나만 남긴다. 입력칸에서는 보이는 이름표가 남는다. 이름표를 되풀이하는 자리 표시 글자와 안내 글은 지운다. 형식을 보여 주는 자리 표시 글자("name@company.com")와 짐작할 수 없는 조건("12자 이상")은 남긴다 |
| U8 | 끊어 쓴 구호 | "빠르게. 쉽게. 확실하게.", "일, 다시 정의하다" | 화면에 이미 있는 말로 "무엇이 무엇을 하는지" 한 문장으로 고치거나 지운다 |

길이: 앱 화면 안의 구역 제목, 카드 제목, 그래프 제목은 다섯 어절 안팎으로 쓴다. 첫 화면의 큰 제목은 한 문장까지 된다.

## 라. 장식 (U9~U11)

| 번호 | 군더더기 | 남기는 경우 |
|---|---|---|
| U9 | 상태와 상관없는 배지 | "NEW", "신규", "인기", "베타", "AI", "🔥 인기"를 분위기로 붙인 것. 앱이 실제로 기록하는 값(새로 올라온 글, 실제 방송 중)에서 그려질 때만 남긴다 |
| U10 | 상태 점 | 깜빡이거나 색이 있는 작은 원(`animate-pulse`, 작은 `rounded-full`). 실제 상태에 묶여 있을 때만 남긴다. 불러오는 중 뼈대 화면의 깜빡임은 상태 점이 아니다. 반복 움직임은 불러오기 표시에만 쓴다(디자인 레퍼런스 지침 3장) |
| U11 | 장식 이모지와 아이콘 | 제목, 단추, 숫자 카드 이름, 기능 목록의 이모지, 기능 카드마다 연한 색 바탕에 넣은 아이콘. 아이콘이 곧 조작 요소일 때(이름이 붙은 아이콘 단추), 글자가 말하지 않는 뜻을 더할 때, 도구 막대나 동작 메뉴(고치기, 복사, 지우기)처럼 모든 항목에 아이콘이 있을 때만 남긴다. 색 바탕 아이콘은 바탕까지 함께 지운다(16 디자인 시작 체크리스트 4-1) |

## 마. 그래프와 대시보드 (U12~U16)

| 번호 | 군더더기 | 할 일 |
|---|---|---|
| U12 | 그래프 종류를 이름으로 단 제목 | "막대 그래프로 본 월별 매출"은 "월별 매출"로 쓴다. 고정된 보고서 그림이면 제목을 발견한 내용으로 써도 된다("3월부터 매출이 두 배"). 실시간 데이터 그래프는 내용이 금방 낡으니 중립 제목을 둔다 |
| U13 | 읽는 법 안내 | "각 막대는 한 달을 나타냅니다", "마우스를 올리면 값이 보입니다". 지운다 |
| U14 | 같은 값을 여러 번 | 막대, 막대 위 숫자, 같은 높이의 격자선, 축 눈금이 모두 같은 값을 말하는 것. 숫자 카드에 화살표, 퍼센트, "증가", 아래 설명 문장까지 붙은 것. 읽는 사람에게 필요한 표시 하나만 남긴다. 숫자 카드는 숫자, 방향 표시 하나, 비교 기간("▲ 12% 지난달 대비")만 둔다 |
| U15 | 데이터보다 눈에 띄는 꾸밈 | 그림 둘레 테두리, 진하거나 촘촘한 격자, 굵은 축, 3D, 그림자, 배경 칠. 지우거나 옅은 회색 실선으로 줄인다. 그래프 종류, 데이터, 계열 색은 바꾸지 않는다 |
| U16 | 이름표로 될 일을 범례로 | 선 끝이나 막대 옆에 계열 이름(가능하면 마지막 값과 함께, "올해 1,150")을 직접 달고 범례를 지운다. 계열이 다섯 개 이상이거나 표시가 너무 붙어 있으면 범례를 둔다 |

## 바. 표면 (U17~U20, 사용자가 화면 꾸밈 정리까지 맡겼을 때만)

화면 꾸밈 정리를 맡기지 않았으면 이 장은 쓰지 않는다. 쓸 때도 **프로젝트에 디자인 시스템 값(색, 간격, 글자 변수, Tailwind 테마, CSS 변수)이 있으면 그 값으로 고치고**, 아래 숫자는 값이 없을 때만 쓴다. 색 묶음, 글꼴, 글자 크기, 모서리, 배치 구조, 구역 순서는 바꾸지 않는다.

| 번호 | 군더더기 | 고칠 값 |
|---|---|---|
| U17 | 색이 바뀌는 그라데이션, 그라데이션 글자, 색 빛 번짐, 흐린 색 덩어리 | 단색 면, 형제 요소와 같은 글자 색, 옅은 실선 테두리. 그림자가 꼭 필요하면 `0 1px 2px rgb(0 0 0 / 0.05)`, 떠 있는 요소는 `0 8px 24px rgb(0 0 0 / 0.06)`까지. 한 색 안의 밝기 변화는 남겨도 된다. 글자 대비는 4.5:1 이상 |
| U18 | 눈금에서 벗어난 간격(`mt-[13px]`, `gap: 7px`) | 4, 8, 12, 16, 20, 24, 32, 40, 48, 64 가운데 가까운 값. 조작 요소 안에서는 2, 6, 10, 14도 된다. 같은 일을 하는 형제(한 목록의 줄, 한 줄의 카드)는 같은 값. 무엇을 정확히 가운데 맞추는 홀수 값은 남긴다 |
| U19 | 지나치게 굵은 글자(800, 900, `font-extrabold`, `font-black`) | 600, 형제가 500이면 500. 위계는 크기와 색으로 준다 |
| U20 | 장식 움직임(`transition-all`, 카드의 `hover:scale`, `animate-bounce`, 튀는 움직임) | 바뀌는 속성만 이름으로 지정(`transition-colors`), 누르기와 켜고 끄기는 120~180ms, 메뉴와 말풍선은 160~220ms, 등장과 배치 바뀜은 300~400ms, 감속 곡선 하나. 누를 때 0.97~0.98로 줄어드는 것은 남긴다. 무엇을 설명하는 움직임은 남긴다 |

## 사. 절차

1. **세기.** 계수기로 후보를 센다.
   ```bash
   python3 ~/.claude/bin/ui-tells.py <파일이나 폴더>
   python3 ~/.claude/bin/ui-tells.py --surface <파일이나 폴더>   # 표면 규칙까지
   ```
   - HTML, JSX, TSX, JS, TS, Vue, Svelte, Astro, Dart, Markdown, CSS, JSON과 ARB 번역 파일을 읽는다. 주석, 테스트 파일, 로그 도구 파일, 자동 생성 Dart 파일은 세지 않는다.
   - 한국어 문구(U4, U5, U9, U12, U13)와 언어와 상관없는 규칙(이모지, 자간 넓은 대문자 클래스, 깜빡이는 점, 그래프 설정, 표면 규칙)을 센다.
   - 정규식으로 찾는 **후보**일 뿐이다. 읽어야 보이는 U3, U4 대부분, U5, U7, U8, U14는 거의 못 찾는다. 반대로 정당한 것도 잡는다. 실제로 잡힌 예: 전화번호 지역번호 `"02"`, 상태 코드 `"NEW"`, 읽음 상태에 묶인 점. 고친 뒤 개수가 0이 아니어도 된다. 0을 맞추려고 정당한 것을 지우지 않는다.
2. **읽기.** 화면의 보이는 글자와 장식을 모두 읽고, 문제마다 U 번호나 05의 조항을 붙인다.
3. **판정.** 많음(대부분의 규칙에 걸리거나 같은 군더더기가 화면 전체에 되풀이됨, 모든 규칙을 차례로 본다), 적음(찾은 것만 고치고 나머지는 그대로 둔다), 없음(고치지 않고 그렇다고 말한다. 고를 수 있는 다듬기는 두 개까지만 적는다).
4. **고치기.** "가. 먼저 정할 것"의 범위 판단을 지킨다.
5. **다시 세기.** 1번과 같은 명령으로 센다.
6. **검토.** 계수기는 읽기 규칙과 안전 규칙을 확인하지 못한다. 바뀐 부분을 다시 읽는다.
   - 남은 부제, 안내 글, 이름표가 U3, U4, U5, U7을 통과하는가
   - 내가 쓴 문구의 사실이 모두 원래 화면과 코드에 있고, 길이 기준 안인가
   - 지운 자리에 빈 감싸개, 자식 하나만 남은 묶음, 남은 여백, 안 쓰는 import가 없는가
   - 입력칸마다 보이는 이름표가 있고, 아이콘 단추마다 이름이 있는가
   - 범위 밖(로직, 데이터, 배치, 표면 정리를 맡지 않았으면 꾸밈)이 바뀌지 않았는가
   - 화면을 띄울 수 있으면(4n5rud-qa) 열어서, 지운 자리에 구멍이 났거나 한 줄에 하나만 남은 곳이 없는지 본다

## 아. 보고

개수표 다음에 세 목록을 쓰고, 빈 목록은 뺀다. 계수기가 세는 규칙은 계수기 숫자를, 나머지는 2번에서 직접 센 숫자를 쓴다. "남김"은 고친 뒤 개수 가운데 일부러 남긴 수다.

| 규칙 | 전 | 후 | 남김 |
|---|---|---|---|
| U1 제목 위 꼬리표 | 5 | 0 | |
| U4 설명 안내 글 | 4 | 0 | |
| U10 상태 점 | 3 | 1 | 1 |

- **새로 쓴 문구:** 내가 쓴 글자 전부를 옛 문구와 새 문구, 규칙 번호로 적는다. 검토하는 사람이 반드시 봐야 하는 부분이다. 지운 것은 바뀐 코드에 보이니 적지 않는다.
  예: `"빠르게. 쉽게. 확실하게." 를 "팀의 지출을 한곳에서 관리합니다" 로 (U8, 지운 첫 화면 문구의 "지출 관리"에서 가져옴)`
- **일부러 남긴 것:** 하나마다 한 줄로 이유를 쓴다. 예: 알림 목록의 점은 읽음 여부에 묶여 있어 남김.
- **할 일:** 찾았지만 고치지 않은 것(서버나 번역 파일에서 오는 글자, 확인할 수 없는 주장, 고객이 정할 일)을 고칠 방법과 함께 적는다.

사용자에게 보고할 때는 08 보고 지침에 따라 파일 위치 대신 화면 이름으로 쓰고, 파일 위치는 괄호 안에 참고로만 붙인다.

## 자. 점검

- [ ] 이미 있는 화면이나 고객이 정한 문구를 고치기 전에 먼저 보고했다.
- [ ] 새로 쓴 문구의 사실은 모두 화면과 코드에 원래 있던 것이다. 지어낸 숫자와 장점이 없다.
- [ ] 남은 배지, 점, 상태 문구는 모두 실제 상태 시험을 통과한다.
- [ ] 접근성 이름과 입력칸의 보이는 이름표가 그대로다.
- [ ] 번역 파일과 서버에서 오는 글자는 출처에서 고쳤거나 할 일로 남겼다.
- [ ] 지운 자리에 빈 감싸개와 남은 여백이 없다.
- [ ] 표면 규칙은 맡았을 때만 썼고, 프로젝트 디자인 시스템 값을 먼저 썼다.
- [ ] 보고에 개수표와 새로 쓴 문구 목록이 있다.
