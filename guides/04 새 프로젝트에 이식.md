# 새 프로젝트에 이식

> 이 문서는 **세션 운영 방식**을 새 프로젝트로 옮기는 최소 절차만 다룬다.
> 공통 틀(받은 자료, 보낼 문서, 할 일, 프로젝트 목록 등록, `.gitignore`)은 새 프로젝트 스킬(4n5rud-new-project)로 먼저 만든다([[12 받은 자료 정리]], [[13 보낼 문서와 발송 상태]], [[14 할 일과 끝낸 일]]).
> 옮기려는 운영 방식은 이렇다. 한 세션이 이슈 하나를 저장소 넘어 끝까지 맡고, 화면 문제는 목업으로 승인을 받고, 고친 뒤 더블체크하고, 메인 세션이 배분과 통합을 맡는다.

---

## 1. 무엇을 옮기나

| 옮기는 것 | 어디로 | 근거 문서 |
|---|---|---|
| 코딩 규칙 | 그 프로젝트에 적용한 결과만 저장소 루트 `CLAUDE.md`에 적는다(사용자가 원할 때) | [[03 코딩 규칙]] |
| 세션 절차 | 새 저장소 `docs/운영/` | [[02 이슈 세션 운영]] |
| 메인 세션 프롬프트 | 붙여넣기 (§3) | [[01 커맨드 센터 운영]] |

**지침서 자체는 복사하지 않는다.** 같은 사실을 두 곳에 두면 한쪽이 반드시 낡고,
낡은 쪽을 읽은 사람이 반대로 움직인다. 저장소에는 **그 프로젝트에 적용한 결과**만 적는다.
원리는 지침서 이름만 적고 경로는 쓰지 않는다.

## 2. 연락 도구 (세션끼리 직접 주고받아야 할 때만)

처음부터 넣지 않는다(§5). 세션 둘 이상이 사람을 거치지 않고 주고받아야 할 때 넣는다. 규칙은 [[00 세션 공통 지침]] §10에 있다.

- **세 파일의 출처:** 지침서 폴더 안 `도구/`의 `말하기.sh`, `find_terminal.py`, `세션.conf.example`
- **필요한 것:** Orca 터미널. 알림을 꽂을 때 `orca terminal` 명령을 쓴다. 다른 도구를 쓰면 `말하기.sh` 안의 `list_terminals`와 `send_text` 두 함수만 바꾼다.

```bash
NEW=<새 프로젝트 경로>
mkdir -p "$NEW/_공유"
# 지침서 도구/ 폴더의 말하기.sh, find_terminal.py, 세션.conf.example 세 파일을 넣는다
cp "$NEW/_공유/세션.conf.example" "$NEW/_공유/세션.conf"
echo "_공유/세션.conf" >> "$NEW/.gitignore"
```

`세션.conf` 에 `<이름>=<워크트리 경로 조각>` 을 **실제 폴더명 그대로** 적는다.

> 🔴 **눈대중으로 적지 않는다.** 하이픈 하나가 달라도 터미널을 못 찾고
> **"터미널 없음" 으로 조용히 빠진다.** 에러가 안 난다. 실제로 당했다.

저장소 루트에서 연결을 확인한다.

```bash
_공유/말하기.sh <아무_세션> "연결 확인"
```

`터미널 없음, 기록만` 이 뜨면 경로 조각이 틀린 것이다.
`세션.conf` 는 **추적하지 않는다**(사람마다 경로가 다르다). 위 명령처럼 `.gitignore`에 넣는다.

⚠ 데이터(대화 기록과 상태)는 **저장소 밖 한 곳**에 둔다. 저장소 안에 두면 워크트리마다
사본이 생겨 **서로의 글을 못 본다.** 통로가 아니라 벽이 된다. 도구만 저장소가 나른다.

## 3. 메인 세션에 붙여넣는 프롬프트

운영 원칙은 지침서에 있으므로 프롬프트에 다시 적지 않는다. 아래를 복사해 **가장 먼저 여는 세션**에 주고, `<>` 만 그 프로젝트 값으로 바꾼다.

```
너는 이 프로젝트의 메인 세션(커맨드 센터)이다. 시작하기 전에 4n5rud-guides 길잡이로
01 커맨드 센터 운영, 02 이슈 세션 운영, 08 보고 지침을 찾아 끝까지 읽어라.
배정, 승인 대기, 더블체크, 보고는 그 세 문서대로 한다.

이 프로젝트의 값
- 저장소 구조: <저장소와 서브모듈 목록, 기본 브랜치>
- 서브에이전트: 동시에 기본 4명(프로젝트 설정으로 바꿀 수 있음)
- 작업 폴더: 세션마다 따로 둔다. <작업 폴더 위치, 예: worktrees/<저장소>/<이름>>
- 보호 브랜치와 예외: <있으면 적는다>
- 금지: <읽기 전용 저장소, 남이 작업 중인 폴더>
```

## 5. 처음부터 다 넣지 않는다

아래 넷은 **세션이 늘어난 뒤에 생긴 것**이다. 처음부터 넣으면 안 쓰는 규칙이 되고,
**안 쓰는 규칙은 나머지 규칙의 무게까지 같이 떨어뜨린다.**

| | 언제 필요해지나 |
|---|---|
| 연락 도구(`_공유/`, §2) | 세션 둘 이상이 사람을 거치지 않고 서로 주고받아야 할 때 ([[00 세션 공통 지침]] §10) |
| 상태판(전체를 HTML 하나로) | 세션이 넷 이상 |
| 발번 충돌 대책 | 문서 번호를 여러 세션이 같이 발번해 자주 겹칠 때, 방법을 사용자에게 제안한다([[00 세션 공통 지침]] §9. 옛 "세션별 번호대 분할"은 레거시) |
| 통합빌드 게이트 | 저장소가 셋 이상이고 포인터를 맞춰 합쳐야 할 때 ([[01 커맨드 센터 운영]] §8) |

## 부록: 규칙마다 붙은 사고

줄이고 싶으면 이 목록을 보고 정한다. 어떤 줄은 그 프로젝트에 아직 해당이 없을 수 있다.

| 규칙 | 없을 때 난 일 |
|---|---|
| 승인 전에 고치지 않는다 | 고쳐 놓고 보고해서 사용자가 되돌릴지를 판단하게 됨 |
| 목업은 실제 값으로 | 눈대중 목업이 한 번에 반려됨 |
| "고쳤다" 는 화면을 보고 | 그럴듯한 설명을 믿고 안 재봐서, 안 고쳐진 것을 고쳤다고 보고 |
| 남이 준 숫자와 서술을 재확인 | 확인 안 한 위험 서술이 문서에 실림 |
| 합친 뒤에도 분석을 돌린다 | 컴파일 안 되는 기본 브랜치가 올라감 (테스트는 초록이었다) |
| `git add -A` 금지 | 대화 기록 속 키가 함께 커밋됨 |
| 데이터는 저장소 밖에 | 워크트리마다 사본이 생겨 서로의 글을 못 봄 |
| 푸시 뒤에 알린다 | "올렸습니다" 인데 상대에게 안 보임 |
| 번호와 ID 용어 금지 | 사용자가 보고를 못 읽음 |
| 올릴 빌드 산출물(앱 설치 파일 등)을 빌드 청소 대상 폴더 밖에 보관 | 다음 빌드의 청소가 올리려던 파일을 지움 ([[앱 세션 지침]] §5) |
