# 받은 자료 정리

> 사용자가 넘겨준 자료는 **그 프로젝트 저장소 안의 `_수신함/`으로 복사하고, 문서에는 저장소 기준 상대 경로로만 적고, 작업과 함께 커밋한다.**
> 다른 사람도 같은 저장소를 받아서 그대로 열 수 있어야 한다. 그래서 **저장소에 남는 글에는 절대 경로를 쓰지 않는다.**

관련 문서: [[15 비밀값 커밋 금지]] §3 (비밀값이 걸렸거나 새어 나갔을 때), [[03 코딩 규칙]] §5 (로컬 전용 목업), [[10 자동 장치]]

## 한눈에 보기

| 할 일 | 규칙 |
|---|---|
| 받은 파일 두기 | 저장소 루트의 `_수신함/<날짜>_<출처>_<내용>/`에 **복사**한다 |
| 문서에 적기 | `_수신함/2026-11-06_카톡_수정요청사항/요청.xlsx`처럼 저장소 기준 상대 경로만 쓴다 |
| 커밋 | 자료와 그 자료를 쓴 작업을 같은 커밋 묶음에 넣는다 |
| 키와 개인 인증 파일 | `_수신함/_비밀/`에 두고 커밋하지 않는다 |
| 큰 파일 | 50MB가 넘는 파일(종류 상관없이)은 `_수신함/_대용량/`에 두고 커밋하지 않는다 |
| 🔴 압축 파일과 보안 정보 | 압축 파일(zip, tar, 7z, rar)은 **어떤 경우에도 올리지 않는다.** 원본은 `_수신함/_비밀/`에만 두고, 푼 내용은 보안 정보를 **두 번 확인하고 가린 뒤** 묶음 폴더에 넣는다(2장 2~3번) |
| 색인 | `_수신함/목록.md`에 한 줄 적는다 |

## 1. 폴더 구조

```
<프로젝트 저장소 루트>/
└─ _수신함/
   ├─ 목록.md                              받은 자료 색인
   ├─ 2026-11-06_카톡_수정요청사항/         한 번에 받은 묶음마다 폴더 하나
   │   ├─ 요청사항_예시.xlsx            파일 이름은 받은 그대로 둔다
   │   └─ 참고 이미지.png
   ├─ 2026-11-04_메일_과업지시서/
   ├─ _비밀/                               커밋 금지 (gitignore)
   └─ _대용량/                             커밋 금지 (gitignore)
```

- **묶음 폴더 이름:** `YYYY-MM-DD_<출처>_<내용>`. 날짜는 받은 날이다. 출처는 `카톡`, `메일`, `슬랙`, `드라이브`, `미팅`, `통화`, `기타` 중 하나를 쓴다. 내용은 짧은 한국어 명사구로 쓰고, 띄어쓰기 대신 밑줄을 쓴다.
- **파일 이름은 바꾸지 않는다.** 받은 쪽과 같은 이름이어야 다시 찾을 수 있다. 같은 이름이 이미 있으면 뒤에 `_2`를 붙인다.
- **여러 저장소로 나뉜 프로젝트**는 문서를 모아 두는 저장소(상위 저장소나 문서 저장소)의 `_수신함/`을 쓴다.
- 이미 `_수신함/` 바로 아래에 흩어져 있는 옛 파일은 억지로 옮기지 않는다. 새로 받는 것부터 이 구조를 따른다.

## 2. 받았을 때 하는 순서

1. **복사한다.** 다운로드 폴더나 임시 폴더(`/var/folders/…`, `/tmp/…`)에 있는 원본을 묶음 폴더로 **복사**한다. 원본을 옮기거나 지우지 않는다. 임시 폴더 경로는 곧 사라지므로 바로 복사한다.
2. **나눈다.** 묶음 폴더에 넣기 전에 저장소 밖 임시 폴더(스크래치패드)에서 한다. 압축 파일은 거기서 풀고, **압축 파일 원본은 `_비밀/`에만 둔다**(압축 파일은 `_수신함/`, `_발신함/`에서 커밋 금지, 커밋 검사가 막는다). 키, 인증서, 서비스 계정 JSON, `*.tfvars`, `.env`, 인증 정보가 든 설정 파일은 `_비밀/`에 둔다. 50MB가 넘는 파일(종류 상관없이)은 `_대용량/`에 둔다.
3. 🔴 **보안 정보를 두 번 확인하고 가린다(2026-11-09 사용자 지시).** 모든 받은 자료에 한다.
   - **1차(도구):** `~/.claude/hooks/secret-scan.sh path <임시 폴더>`로 검사한다. 걸린 값은 `secret-scan.sh mask <임시 폴더>`로 `<가림>` 처리한다. 가리기 전 원본이 필요하면 `_비밀/`에 둔다.
   - **2차(눈):** 다시 `path`로 검사해 깨끗한지 보고, 남은 파일을 직접 훑는다. 도구가 못 찾는 계좌번호, 주민등록번호, 전화번호, 주소, 문장 속 비밀번호, 화면 캡처 속 키를 찾아 가린다.
   - 두 번 모두 깨끗해야 묶음 폴더로 옮긴다. 이미 노출된 키는 먼저 재발급을 요청한다([[15 비밀값 커밋 금지]] §3).
4. **적는다.** `_수신함/목록.md`에 한 줄 더한다.
   ```
   | 2026-11-06 | 카톡 | 수정요청사항 1106 | `2026-11-06_카톡_수정요청사항/` | `docs/수정요청_처리기록.md` |
   ```
   열은 받은 날, 출처, 내용, 폴더, 이 자료를 반영한 문서다.
5. **쓴다.** 문서와 코드에서 자료를 가리킬 때는 저장소 기준 상대 경로만 쓴다.
6. **커밋한다.** 자료와 그 자료를 반영한 작업을 함께 커밋한다. 자료만 먼저 올려도 된다(`docs(inbox): 11.06 카톡 수정요청사항을 수신함에 추가함`). `_비밀/`과 `_대용량/`은 처음 만들 때 저장소 `.gitignore`에 넣는다.

## 3. 🔴 저장소에 남는 글에는 절대 경로를 쓰지 않는다

- 저장소에 남는 글(문서, 코드, 설정, 커밋 메시지, PR, 이슈)에는 절대 경로를 쓰지 않는다. 다른 세션이나 서브에이전트에 넘기는 글도 저장소 안의 파일은 저장소 기준 경로로 가리킨다.
- 예외: 저장소 밖 지침서처럼 저장소 경로로 가리킬 수 없는 것을 세션에 넘길 때는 경로를 써도 된다. 이 글은 저장소에 남기지 않는다.
- 쓰지 않는 것: `/Users/<이름>/…`, `/home/<이름>/…`, `C:\Users\<이름>\…`, `~/Downloads/…`, `/var/folders/…`, `/tmp/…`, `/private/…`
- 대신 쓰는 것:
  - 저장소 안의 파일: 저장소 루트 기준 상대 경로(`_수신함/…`, `docs/…`)
  - 다른 저장소의 파일: 저장소 이름과 그 안의 상대 경로(`<저장소 이름>/docs/…`)
  - 저장소 밖에만 있는 것: 경로 대신 무엇인지 설명한다("메일로 받은 견적서 원본, 보관 위치는 담당자에게 문의")
- **왜:** 절대 경로는 그 사람의 컴퓨터에서만 열린다. 다른 사람이 저장소를 받으면 깨진 링크가 되고, 사용자 이름과 폴더 구조가 그대로 드러난다.

## 4. 지키는 장치

사용자 메시지에 저장소 밖 파일 경로가 들어오면 이 문서대로 정리하라는 알림이 오고, 커밋에 개인 절대 경로, 키와 인증 파일, `_수신함/`과 `_발신함/` 아래 압축 파일이 섞이면 막힌다. 비밀값 검사는 [[15 비밀값 커밋 금지]], 장치 동작은 [[10 자동 장치]].
