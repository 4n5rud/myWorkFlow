# 앱 세션 지침

> 이 문서는 세션을 나누는 기준이 아니라 앱을 건드릴 때 펴는 참고 자료다(자세한 규칙: [[03 코딩 규칙]] §8).
>
> 먼저 [[00 세션 공통 지침]]을 읽는다. 여기는 **앱 고유의 것**만 적는다.
> 앱의 결함은 **사용자에게 바로 보인다.** 그리고 고쳐도 **스토어 심사만큼 늦게** 도달한다.
> 예시 명령과 코드는 Flutter와 안드로이드 기준인 곳이 있다. 그런 곳에는 "(Flutter 예)", "(안드로이드)"를 붙였다.

---

## 1. 🔴 낡은 `TODO` 주석

`TODO(api)`의 "서버에 없다"를 믿었는데 서버에 진작 있던 사례는 [[00 세션 공통 지침]] §2에 있다. 앱은 서버보다 늦게 따라가는 구조라 이 주석이 특히 잘 낡는다.

- 세션 시작 때 `TODO(api)` 류를 **전수로 뽑아 계약과 대조**하는 것을 루틴으로 둔다. 계약 yaml, 서버 DTO, 라이브 라우트를 직접 연다.
- 프로젝트 규약 문서(CLAUDE.md 등)도 낡는다.
  > 권한 관련 절이 **재설계 이전 내용**으로 남아 있어, 믿고 작업하면 **없애기로 한 권한을 다시 넣게** 돼 있었다.

## 2. 🔴 화면이 아예 안 뜨는 것을 못 보고 지나간다

> 핵심 기능 화면이 **한 번도 뜬 적이 없었다.**
> `build()`가 `Future<T?>`를 `Future<T>`로 다운캐스트해 **매번 타입 에러**였다(Flutter 예).
> **서버는 200을 주고 있었다.**

- 서버 응답이 정상이라고 화면이 뜨는 게 아니다. **눈으로 본다.**
- nullable 다운캐스트는 컴파일을 통과하고 **런타임에만 터진다.** 특히 빌드 메서드 안에서 조심한다.

## 3. 값이 없으면 침묵하고, 거짓말하지 않는다

> 보관함이 **모든 행에 "미사용"** 을 표시하고 있었다. 계약에 그 값이 없어서 기본값이 찍힌 것이다.
> 지금은 값이 없으면 **아무것도 표시하지 않는다.**

- 없는 값을 **기본값으로 채워 보여주지 않는다.** 사용자는 그걸 사실로 읽는다.
- 계약에 없는 필드를 화면이 요구하면 **그건 계약 요청 대상**이지 클라이언트가 지어낼 것이 아니다.

## 4. 서버와의 배포 순서

서버 거절 로직 배포, 앱의 플래그 전송, 앱의 로컬 차단 제거 순서를 지킨다. 앱은 없는 필드에 관대해야 한다. 자세한 규칙: [[백엔드 세션 지침]] §9.

## 5. 설치와 빌드가 조용히 실패한다

- **`adb install`의 `Success`를 믿지 않는다**(안드로이드). 실제로 Success인데 안 깔려 있었다.
  ```bash
  adb shell pm path <패키지명>     # 이걸로 확인한다
  ```
- **핫리로드로 검증하지 않는다.** 빌드해서 설치한 것만 검증으로 친다.
- 빌드 인자는 **손으로 조립하지 않는다.** 정의 파일을 쓴다(Flutter 예: `--dart-define-from-file`).
- 버전 관리 도구가 있으면 **PATH의 것을 쓰지 않는다**(Flutter 예: `fvm flutter`).

### 🔴 빌드와 배포에서 당한 것

| | 함정 | 결과 |
|---|---|---|
| 🔴 | **빌드 인자를 손으로 조립** | 키 몇 개가 빈 채로 구워져 **소셜 로그인이 전부 "준비 중"**. 빌드는 성공했고 테스트도 초록이었다. 빈 키는 조용히 기능만 끈다 |
| 🔴 | **검사가 넣으려던 파일만 본다** | 구운 결과물은 안 봤다. **파일은 맞는데 산출물엔 안 들어간** 경우를 못 잡는다 |
| 🔴 | **플랫폼마다 키 경로가 다르다** | 네이티브 SDK 키는 dart-define으로 안 간다(Flutter 예). 한 플랫폼만 검사하면 **다른 쪽은 무방비** |
| 🔴 | **청소가 남의 산출물을 지운다** | 한 대상을 구우면 **앞서 구운 다른 대상이 같이 사라진다.** 올리려던 파일이 없어져 있었다 |
| ⚠ | **권한 사유문 누락** | iOS는 모션 데이터에 닿는 순간 **프로세스를 끝낸다.** 팝업이 안 뜨는 정도가 아니라 앱이 죽는다 |

**대응은 하나로 모인다: 산출물을 열어서 확인한다.** 넣으려던 것이 아니라 나온 것을 본다.
그리고 그 확인을 **스크립트로 박아** 다음 사람이 기억에 기대지 않게 한다.

### 🔴 실기기를 건드리기 전에

- 설치하거나 조작하기 전에 **그 폰의 맨 앞 앱이 무엇인지 확인한다**(안드로이드: `adb shell dumpsys activity activities`). 다른 프로젝트 앱이나 개인 앱이 열려 있으면 손대지 않고 사용자에게 묻는다. 한 폰을 여러 작업이 같이 쓴다.
- 설치 명령은 **실패하면 멈추고 보고하게** 쓴다. `||`로 "지우고 다시 설치" 같은 대체 경로를 붙이지 않는다.
- 명령을 중단할 때는 **뒤에 이어지는 명령이 실행되지 않는지** 확인한다.
- 서명 불일치 등으로 재설치가 필요하면 그 사실을 먼저 알리고 허락을 받은 뒤 한다(앱 데이터가 지워진다).

> 실제 사고: 걸린 `adb install -r`를 중단했더니 붙여 둔 `|| { uninstall; install; }`가 실행되어 앱이 지워졌다가 다시 깔렸고, 그 폰에서 다른 작업이 쓰던 앱이 뒤로 밀렸다.

### 🔴 실기기를 누를 때 (2026-11-10 규칙)

사용 허락을 받은 폰이어도 사람이 동시에 쓸 수 있다.

- **누르기 전마다 맨 앞 앱이 내 앱인지 확인한다.**
- 앞 화면이 조작 없이 저절로 바뀌거나 화면 캡처가 막히면 **즉시 멈추고 보고한다.**
- 뒤로 가기는 좌표로 누르지 않고 `KEYCODE_BACK`을 보낸다(안드로이드).
- 누를 곳은 `uiautomator dump`로 찾은 요소의 영역 가운데만 누른다(안드로이드). 짐작한 좌표를 누르지 않는다.
- 글 본문(링크가 있을 수 있는 자리)은 누르지 않는다.
- 엉뚱한 앱이 열려도 남이 쓴다고 섣불리 단정하지 않는다. 내가 잘못 눌렀을 수 있다.

> 실제 사고: 좌표로 누른 자리가 다른 앱을 열었다. 같은 날 뒤로 가기 화살표 자리를 좌표로 눌렀는데 쇼핑 앱이 열렸다. 본문 속 링크를 누른 것으로 보인다.

## 6. 실기기로 눈으로 볼 것을 목록으로 남긴다

세션이 끝날 때 **검증 안 된 화면**을 표로 남긴다. 다음 세션이 그것부터 본다.

특히 잘 빠지는 것:

```
[ ] 푸시: 포그라운드, 백그라운드, 앱 종료 상태, 딥링크 종류별
[ ] 뒤로가기와 닫기 (화면마다)
[ ] 권한 거부 후 재요청 경로
[ ] 오프라인과 재연결
[ ] 밝기, 화면 유지 같은 부수효과의 원복
[ ] 저사양, 구형 기기
```

> 푸시는 **네 가지 상태가 전부 다른 코드 경로**다. 하나 고쳤다고 나머지가 되는 게 아니다.

## 7. 목데이터는 지우는 방법까지 남긴다

서버에 넣는 시드와 목데이터는 식별 가능하게 만들고 지우는 기준을 인계 문서에 적는다. 자세한 규칙: [[백엔드 세션 지침]] §8 "서버 시드 데이터". 앱 안에서만 쓰는 로컬 목업 JSON은 커밋, 푸시, 빌드에 넣지 않는다([[03 코딩 규칙]] §5).

## 8. 에러 코드는 앱이 지어내지 않는다

- 서버에 없는 코드가 필요하면 **기획에 발번을 요청**한다.
- 임시로 버텨야 하면 **접두사를 다르게** 해서 카탈로그 번호를 **미리 점유하지 않는다**(예: `APP_*`).
- 정식 코드가 생기면 **임시 코드를 지운다.** 잔재가 남으면 다음 사람이 뭘 믿을지 모른다.
- 문구는 **카탈로그가 정본**이다. 앱에서 고쳐 쓰지 않는다.

## 9. 권한과 백그라운드

- **요구 권한을 최소로 유지하는 설계**를 지킨다. 늘리는 순간 스토어 심사 리스크가 붙는다.
- OS 권한 팝업 **전에 목적 안내**를 먼저 띄운다. 거부율이 다르다.
- 백그라운드 동작은 **OS 이벤트 기반**으로 짜고 연속 추적을 피한다. 배터리와 심사 둘 다에 걸린다.
- 규약 문서에 적힌 권한 정책이 **재설계 이전 것**일 수 있다(§1). 코드와 대조한다.

## 10. 배포 전 필수

```
[ ] 지도, 분석 등 외부 서비스 키: 임시, 개인 키를 운영 키로 교체하고 도메인과 패키지 제한
[ ] iOS 배포 프로파일 (개발용 프로파일이 남아 있지 않은지)
[ ] 푸시 자격증명 (APNs 키 업로드 여부)
[ ] API 키 제한 (패키지와 서명, 번들 ID)
[ ] 스토어 심사 일정을 개발 일정과 별도로 확보
```

⚠ 키가 **여러 개고 이름이 비슷하다.** 지도 SDK 키와 로그인 앱 키는 다른 것이다.
**남의 담당 키를 건드리지 않는다.**

```
[ ] 🔴 사용자에게 보이던 결함과 원인
[ ] 검증 안 된 화면 목록          (§6, 이게 제일 중요하다)
[ ] 목데이터 위치와 지우는 기준    (백엔드 지침 §8)
[ ] 서버나 웹이 움직여야 풀리는 것
[ ] 배포 전 필수 목록의 현재 상태  (§10)
[ ] 테스트 기기와 계정 (비밀번호는 값이 아니라 위치만)
```
