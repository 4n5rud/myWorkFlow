# 기획 세션 지침

> 이 문서는 세션을 나누는 기준이 아니라 기획 문서를 건드릴 때 펴는 참고 자료다(자세한 규칙: [[03 코딩 규칙]] §8).
>
> 먼저 [[00 세션 공통 지침]]을 읽는다. 여기는 **기획과 명세 고유의 것**만 적는다.
> 기획은 **코드를 짜지 않고 사실을 정하는** 일이라, 여기서 틀리면 구현이 같이 틀린다.
>
> 문서 이름, ID 형식, 폴더 구조는 한 프로젝트에서 쓴 **예시**다. 프로젝트마다 다르니 착수할 때 그 프로젝트의 것을 확인한다.

---

## 1. 권위 순서를 먼저 세운다

충돌하면 **위가 이긴다.** 프로젝트마다 다르므로 착수 시 확인하고 문서로 못 박는다. 예시:

1. 원본: RFP(제안요청서), 회의록, 클라이언트 확답, 화면정의서
2. SoT yaml(단일 원본, Source of Truth): 화면 인벤토리, 에러 카탈로그, 데이터모델, 권한
3. 명세 md: 화면 명세, 기능 명세
4. 파생물: 인계, 분석, 보고 문서

- **원본은 불변**이다. 편집하지 않고, 바뀌면 새 입력으로 추가한다.
- 색인 문서(BRIEF처럼 여러 문서를 요약해 가리키는 문서)는 **SoT가 아니다.** 편하다고 색인만 보고 답하지 않는다.
- 카톡이나 메일 확답은 **정형화해서 날짜, 발화자와 함께** 남긴다. 원문이 없으면 나중에 대조할 방법이 없다.

> 실제로 구현명세가 **클라이언트 원문의 괄호 둘을 잘라먹은 것**이 뒤늦게 발견됐고,
> 이어서 3건이 더 나왔다. 원본 확보를 미루지 않는다.

## 2. 같은 사실을 두 곳에 쓰지 않는다

레이어별 소유권을 정하고 지킨다. 예시:

| 사실 | SoT |
|---|---|
| 화면 목록, ID, 부모 | 화면 인벤토리 |
| 엔드포인트 상세 | API 계약(OpenAPI), **기능명세에 나열 금지** |
| 스키마와 필드 | 데이터모델 |
| 권한 | 권한 매트릭스 |
| 에러 문구와 코드 | 에러 카탈로그 |

두 곳에 쓰면 **한쪽이 반드시 낡는다.** 낡은 쪽을 읽은 사람이 반대로 구현한다.

## 3. 변경은 개선 문서를 먼저 열고 시작한다

순서(문서 이름은 예시):

1. 개선 문서(IMP, improvement의 약자) 생성
2. 전파
3. 반영 체크리스트 채움
4. status와 INDEX(문서 목록) 갱신

전파 순서를 **건너뛰지 않는다.** 위에서 아래로:

1. 화면 인벤토리
2. 화면 명세
3. 기능 명세
4. API 계약
5. 에러 카탈로그, 데이터모델, 권한
6. 디자인 브리프, 컴포넌트 카탈로그
7. 화면 HTML

개선 문서에는 **결정만 적지 말고 기각한 대안과 이유**를 같이 적는다.
다음 세션이 같은 논의를 반복하지 않게 하는 게 이 문서의 값이다.

## 4. ⚠ 미러 동기화: 가장 많이 빠뜨린다

같은 파일이 두 경로에 **사본으로** 존재하는 구조가 흔하다(편집용, 검증 스크립트가 읽는 용).
**한쪽만 고치고 커밋하면 검증이 통째로 무력해진다.**

```bash
diff -rq <A경로> <B경로> | grep differ     # differ 행만 본다
```

- `diff -rq`는 한쪽에만 있는 파일도 `Only in...`으로 뱉는다. **정상인 경우가 많으니 `differ`만** 본다.
- ⚠ **반대 방향 드리프트**를 조심한다. 전파 전에 `<` 행을 훑어 **받는 쪽에만 있는 결정**이 없는지 본다.
  구판이면 덮어써도 되고, 독립 결정이면 **먼저 백포트**한다. 이걸 안 해서 확정을 되돌릴 뻔한 적이 있다.
- 화면 하나가 **파일 4개**인 구조도 있다(도메인 폴더, 평면 사본, 각각의 미러). 하나만 고치지 않는다.

## 5. ID 규약: 지어내지 않는다

- 모르거나 미정이면 **지어내지 말고** 미결정 번호를 달아 남긴다(예: `(O-nn, PM 확정필요)`. O-nn은 미결정 항목 번호).
- **dangling 0**(존재하지 않는 ID 인용), **orphan 0**(어디서도 인용 안 되는 사용자 노출 에러).
- **재번호와 재사용 금지.** 폐지한 ID는 폐지로 남기고 **다시 쓰지 않는다**. 과거 기록이 그 ID를 가리키고 있다.
- 변경 근거는 본문에 인라인으로 적는다(예: `(클라 7/30 요구)`, `(PM 재량 확정)`, `(구현 정합)`).
- 여러 세션이 같은 번호를 동시에 가져가는 문제는 [[00 세션 공통 지침]] §9를 본다.

> 인벤토리에 없는 화면을 **SoT 4곳이 근거로 인용**하고 있던 사례가 있다.
> 와이어프레임과 프로토타입은 있는데 인벤토리 등록만 빠진 것이었다. 패리티 검사가 이걸 잡는다.

## 6. 명세가 시킨 것만 보지 않는다

> 백엔드 세션이 중복 인증 방지를 점검하러 갔는데 **방지 자체는 멀쩡했고**,
> 진짜 구멍은 **명세가 말하지 않은 곳**에 있었다. 승인도 안 난 이벤트가 진짜 보상을 주고 있었다.

**기획이 안 적어서 생긴 구멍**이다. 기능을 적을 때 그 **옆에 뚫려 있는 것**을 같이 본다.
상태 게이트, 권한 경계, 전제 조건이 특히 잘 빠진다.

## 7. 숫자의 출처를 끝까지 따라간다

> 비기능 요구사항에 "동시 접속 아주 많아도 무장애"가 목표로 적혀 있었다. 출처를 따라가니
> **다른 프로젝트 실적으로 든 숫자**(그만큼 처리했다는 신뢰 근거)였다.
> 이 프로젝트의 요구가 아니었는데 **목표로 승격**돼 있었고, 그 숫자로 인프라를 사면 비용이 몇 배로 난다.

- 성능과 부하 수치는 **어디서 왔는지** 반드시 적는다.
- **약속(우리가 할 수 있다)** 과 **요구(이만큼 해야 한다)** 를 구분한다.
- 원본에 없으면 **없다고 적는다.** 추정을 확정처럼 쓰지 않는다.

## 8. 미결정을 정직하게 관리한다

- 미결정(O)과 충돌(C)은 **임의로 봉합하지 않는다.** 노출한 채로 둔다.
- 다만 **해소된 것을 계속 미결정으로 두지도 않는다.** 한쪽에서 "확정됐다"고 하고
  다른 여섯 곳이 "미결정"으로 남아 있는 상태가 실제로 있었다. **읽는 사람이 어느 쪽을 볼지 모른다.**
- 미결정에 **기본값(선반영)** 을 넣었으면 그렇게 적고, 런타임 토글로 뒤집을 수 있게 설계한다.

## 9. 검증

문서를 고친 뒤 돌린다. **무엇을 실제로 봤는지** 확인한다([[00 세션 공통 지침]] §7).

프로젝트에 패리티 검사 스크립트가 있으면 돌린다. 한 프로젝트에서는 인벤토리, 명세, 와이어, 프로토가 같은지(패리티)와 커버리지, 화면 상태, 죽은 클릭, 인증 경계, 운영 UI 범위를 스크립트로 봤다.

```bash
# 예: 프로젝트의 검사 스크립트
python scripts/check-*.py

# yaml 은 파싱까지
python -c "import yaml,sys;yaml.safe_load(open(sys.argv[1],encoding='utf-8'))" <파일>
```

⚠ 검증 스크립트의 **간이 파서가 yaml 전체 문법을 못 읽는 경우**가 있다.
블록 스칼라(`>`)를 쓴 순간 **14개 코드가 통째로 dangling으로 잡힌** 적이 있다. 한 줄 문자열로 쓴다.

## 10. 함정 모음

- **symlink 스텁**: 일부 명세 파일이 git symlink라, symlink를 지원하지 않는 체크아웃(Windows 등)에서는 **파일명 한 줄짜리 텍스트**로 보인다.
  **덮어쓰지 않는다.** 실체는 슬러그 파일이다.
- **생성물 손편집 금지**: 스크립트가 만드는 파일(계약 yaml, 번들 md)은 손으로 고치지 않는다.
  고치면 다음 생성 때 날아가거나, 생성기와 어긋난다.
- **통합본(_generated) stale**: 자동 생성 통합본이 **원본보다 뒤처져** 있는 경우가 흔하다.
  통합본만 읽고 판단하지 않는다. 개수부터 세어 본다.
- **평면 사본**: 도메인 폴더와 별도로 평면 사본이 손으로 유지되는 구조면 **같이 고친다.**

## 인계 문서에 꼭 담을 것

공통 항목(가장 크게 당한 것, 남에게 물어 놓은 것, 안 하기로 한 것과 이유, 재현 방법, 확인하지 못한 것 등)은 [[00 세션 공통 지침]] §8을 따른다. 기획에서 더 담을 것:

```
[ ] 이번에 확정된 것 (근거, 날짜, 발화자)
[ ] 미결정 목록과 각각의 권고안
[ ] 다음 세션이 바로 할 수 있는 것 (막힌 게 없는 것부터)
```
