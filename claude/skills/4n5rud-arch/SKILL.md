# 구조 지도와 런북

사용자가 AI 없이도 프로젝트를 이해하고, AI가 멈췄을 때도 기본 대응을 할 수 있게 돕는 문서 두 개를 만든다. 목적은 학습이다. 사용자가 읽고 **한 번은 직접 따라 해 볼 수 있는** 수준으로 쓴다.

먼저 읽을 것: 4n5rud-guides 스킬로 `08 보고 지침.md`, `17 기술 문서 쓰기.md`, `05 쇠맛 줄이기.md`(1장, 4장, 8장)를 찾아 읽는다.

## 1. 대상

- 인자가 프로젝트 이름이면 그 프로젝트 하나. 저장소 위치는 `~/.claude/harness/projects.md`에서 찾는다.
- `전체`면 그 목록의 프로젝트마다 서브에이전트를 하나씩 맡긴다(한 번에 한도 안에서, 기본 4명). 각자 이 스킬 파일을 읽고 프로젝트 하나만 만든다.

## 2. 근거 (가장 중요)

- **저장소에서 확인한 것만 쓴다.** 줄마다 근거 위치(저장소 기준 상대 경로, 필요하면 줄 번호)를 괄호로 붙인다. 원격 기준으로 본다(`git fetch` 뒤 기본 브랜치나 통합 브랜치).
- 읽을 곳: README, 패키지와 빌드 설정(package.json, pubspec.yaml, build.gradle, Dockerfile, docker-compose), 진입점(main, app, server, routes), 설정과 환경 변수 견본(.env.example), 배포 스크립트와 CI, docs와 운영 문서, 서브모듈 목록, 최근 인계 메모.
- 확인하지 못한 칸은 지어내지 않고 **"확인 필요"**로 비우고 무엇을 확인해야 하는지 적는다. 운영 서버 주소, 계정, 키 값은 쓰지 않는다(이름과 위치만, 지침서 15).
- 코드나 설정은 고치지 않는다. 읽기만 한다.

## 3. 만들 것

프로젝트 문서 저장소의 `_작업/구조/`에 두 파일을 둔다. **사용자 학습용이라 커밋하지 않는다.** 만들기 전에 그 저장소의 로컬 제외 목록(`$(git rev-parse --git-common-dir)/info/exclude`, 커밋되지 않는 파일)에 `_작업/구조/` 줄이 있는지 보고, 없으면 더한다. 공용 `.gitignore`는 고치지 않는다. 이미 있으면 덮어쓰지 말고 바뀐 곳만 고치고, 맨 위 "갱신" 줄에 날짜와 무엇이 바뀌었는지 더한다(00 §14).

### `구조 지도.md`

장 이름만 정한다. 각 장의 내용은 그 저장소에서 확인한 사실로만 채운다.

1. 한눈에 보기: 이 시스템이 무엇을 하는지 두세 문장, 구성 요소 그림(텍스트 상자 그림이나 표)
2. 구성 요소: 저장소나 서비스마다 역할, 스택, 저장소 위치, 진입점
3. 요청 한 개 따라가기: 대표 화면 하나에서 시작해 앱이나 웹, API, 서버 처리, DB까지 가는 길을 단계별로(파일 위치 포함)
4. 데이터: 주요 테이블이나 저장소와 주인(어느 구성 요소가 쓰고 읽는지)
5. 외부 연동: 연동 대상, 방식, 실패하면 어떻게 되는지
6. 설정과 비밀값 위치: 환경 변수 이름과 파일 위치만
7. 배포 경로: 어디서 빌드하고 어디에 올라가는지, 되돌리는 방법
8. 구조 결정과 이유: 저장소 문서에서 찾은 결정만(못 찾으면 "확인 필요")
9. 스택이 바뀌어도 남는 개념: 이 구조가 기대는 개념 세 가지와, 다른 스택에서는 어떻게 생겼는지 한 줄씩

### `런북.md`

1. 로컬에서 띄우기: 명령을 순서대로(실제 스크립트 근거)
2. 로그 보는 곳: 로컬, 개발, 운영(위치만, 운영 접근은 "권한 확인 필요")
3. 배포하기와 되돌리기
4. 자주 나는 장애와 확인 순서: 인계 메모, 이슈, 장애 기록에서 찾은 실제 사례 위주. 계층(네트워크, 인증, 빌드, 데이터, 코드)을 먼저 좁히는 순서로
5. 막혔을 때 누구에게(역할만, 이름은 프로젝트 문서에 있는 만큼)
6. **직접 따라 해 보기:** 사용자가 AI 없이 해 볼 체크 칸 세 개(예: 로컬에서 띄우기, 로그에서 최근 오류 하나 찾기, 요청 한 개 경로를 코드에서 따라가기). 해 보면 사용자가 날짜를 적는다.

## 4. 보고 (한국어, 짧게)

- 만든 파일과 위치, 근거가 있는 칸과 "확인 필요"로 남긴 칸의 수
- 사용자가 이번 주에 직접 따라 해 보면 좋을 것 하나
- 08 보고 지침을 따른다. 내부 약어 대신 기능 이름으로 쓴다.
