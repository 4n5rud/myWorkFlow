# 새 프로젝트 시작하기

인자: $ARGUMENTS (프로젝트 이름. 저장소 주소나 폴더를 함께 줄 수 있다)

먼저 읽을 것: 4n5rud-guides 스킬의 길잡이 표, `{{GUIDES_DIR}}/04 새 프로젝트에 이식.md`(세션 운영을 옮길 때. 공통 틀은 이 스킬이 만든다), `12 받은 자료 정리.md`, `13 보낼 문서와 발송 상태.md`, `14 할 일과 끝낸 일.md`. 보고와 문장은 08 보고 지침과 05 쇠맛 줄이기를 따른다.

## 1. 정할 것 모으기

이미 있는 것부터 확인하고, 알 수 없는 것만 **한 번에** 묻는다(AskUserQuestion 한 번).

| 항목 | 먼저 확인할 곳 | 기본값 |
|---|---|---|
| 프로젝트 이름(노트 보관함 폴더 이름) | 인자 | 없음, 꼭 받는다 |
| 저장소 폴더 | 인자, `{{WORK_DIR}}` 아래 같은 이름 폴더 | 원격 주소를 받으면 `{{WORK_DIR}}/<저장소 이름>`에 받는다(`git clone`) |
| 문서 저장소(`_수신함`, `_발신함`, `_할일`을 둘 곳) | 저장소가 하나면 그 저장소, 여럿이면 상위나 문서 저장소 | 저장소가 하나면 묻지 않는다 |
| WBS 위치 | 저장소 안 `wbs`, `WBS`가 들어간 파일 | 없음 |
| 주간보고 대상 여부 | | 대상 |
| 주간보고 성명, 부서 | 저장소 `docs/weekly_report/` 규칙 | `harness.conf`의 값 |

- `{{HARNESS_DIR}}/projects.md`에 같은 이름이 이미 있으면 멈추고 알린다(중복 등록 금지).
- 저장소가 `harness.conf`의 읽기 전용, 커밋 금지 목록에 있으면 그 저장소에는 아무것도 만들지 않고 알린다.

## 2. 프로젝트 목록 등록

`{{HARNESS_DIR}}/projects.md`의 표에 한 줄을 더한다. 주간보고 대상이 아니면 "제외 프로젝트"에 이유와 문서 저장소를 적는다. 이 파일은 이 컴퓨터 전용이라 커밋하지 않는다.

## 3. 문서 저장소에 공통 틀 만들기

```
_수신함/목록.md          받은 자료 색인 (커밋함)
_수신함/_비밀/           키, 인증 파일, 가리기 전 원본 (커밋 금지)
_수신함/_대용량/         50MB 넘는 파일 (커밋 금지)
_발신함/목록.md          보낼 문서 상태 (로컬 전용, 커밋 금지)
_할일/할 일.md           남은 일 (로컬 전용, 커밋 금지)
_할일/끝낸 일.md         끝낸 일 기록 (로컬 전용, 커밋 금지)
```

- 이미 있는 파일은 덮어쓰지 않는다.
- 각 목록의 머리말과 표 머리는 지침서 12, 13, 14의 형식을 그대로 따른다. `할 일.md`에는 "세션이 처리할 것", "사용자 확인 기다림" 두 소제목을 둔다.
- `.gitignore`에 아래 네 줄이 없으면 더한다.
  ```
  _수신함/_비밀/
  _수신함/_대용량/
  _할일/
  _발신함/목록.md
  ```
- 커밋은 `.gitignore`와 `_수신함/목록.md`만 경로를 지정해서 한다. 메시지는 저장소 관례 접두사와 09 커밋 메시지 규칙을 따른다(예: `chore: 받은 자료 폴더와 커밋 금지 목록을 추가함`).
- 어느 브랜치에 커밋할지는 문서 저장소가 서브모듈을 묶는 상위 저장소인지(`.gitmodules`가 있는지)에 따라 다르다.
  - **상위 저장소이면** 기본 브랜치(main이나 master)에서 바로 커밋한다. 상위 저장소는 기본 브랜치에서만 작업하고 기능 브랜치는 서브모듈에서 나누기 때문이다(00 세션 공통 지침). 기본 브랜치 푸시는 검사 결과를 보여 주고 사용자 승인을 받은 뒤에 한다.
  - **상위 저장소가 아니면** 지금 브랜치가 보호 브랜치(dev, main, prod, staging)일 때 작업 브랜치(`chore/project-setup`)를 만들어 거기에 커밋한다. 보호 브랜치로 푸시하거나 머지할 때는 검사 결과를 보여 주고 사용자 승인을 받는다.
- 저장소 문서에는 절대 경로와 개인 노트 위치를 쓰지 않는다(커밋 검사가 막는다).

## 4. 노트 보관함

- `{{NOTES_DIR}}/work/<프로젝트>/` 폴더를 만든다.
- 그 안에 `할 일.md`, `끝낸 일.md` 바로가기(symlink)를 만들어 문서 저장소의 `_할일/` 두 파일을 가리키게 한다. 원본을 노트 보관함에 따로 만들지 않는다.
- 이번 주 주간 폴더와 주간목표가 필요하면 weekly-work-notes 스킬로 만들지 사용자에게 한 줄로 제안한다(자동으로 만들지 않는다).

## 5. 처음부터 다 넣지 않는다

04 이식 지침 5장대로, 세션이 여럿으로 늘기 전에는 상태판, 번호대 분할, 통합 빌드 게이트, 세션 연락 도구를 넣지 않는다. 저장소 `CLAUDE.md`, `docs/운영/`도 사용자가 원할 때만 만든다. 만들 때는 그 프로젝트에 적용한 결과만 적고, 개인 노트의 지침서 위치는 적지 않는다.

## 6. 확인

- `git check-ignore`로 `_할일/할 일.md`, `_발신함/목록.md`, `_수신함/_비밀/x`가 무시되는지 본다.
- `~/.claude/hooks/personal-scan.sh <문서 저장소>`가 깨끗한지 본다.
- 노트 보관함 바로가기가 실제 파일을 여는지(`cat`) 본다.

## 7. 보고

08 보고 지침대로 결론부터 쓴다.
- 만든 것: 폴더와 파일. 커밋한 것과 커밋하지 않은 것을 나눈다.
- 등록한 값: 프로젝트 목록의 한 줄.
- 직접 확인하는 방법: `/4n5rud-todo <프로젝트>`, 새 세션을 열면 할 일 개수를 알려 주는지.
- 남은 결정: 푸시할지, 주간 폴더를 만들지, WBS 위치를 모르면 그 사실.
