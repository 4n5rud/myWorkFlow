# 저장 공간 정리

캐시와 다시 받아야 하는 것은 건드리지 않는다. 사용자가 다시 쓸 일이 없는 **파일 산출물**만 찾아 묶음으로 보여 주고, 고른 것만 지운다. 문장은 08 보고 지침과 05 쇠맛 줄이기를 따른다.

## 1. 찾기 (읽기만)

1. `df -h /`로 지금 남은 공간을 본다.
2. `python3 ~/.claude/bin/cleanup-scan.py`를 돌린다. 묶음별 크기와 개수, 위치별 합계가 나오고, 번호가 붙은 전체 목록이 `~/.claude/harness/cleanup/last-scan.tsv`에 남는다.
3. 묶음 3(앱 빌드 산출물)과 6(목업, 캡처)은 목록을 열어 무엇이 있는지 직접 본다. 같은 앱의 여러 판이 있으면 가장 최근 것 하나는 남기는 쪽을 권한다(`--keep-latest`).

찾는 묶음: 1 설치 파일(dmg, pkg), 2 다운로드 중복 파일("(1)" 꼴이고 원본이 있는 것), 3 앱 빌드 산출물(apk, aab, ipa), 4 화면 녹화와 영상(14일 넘은 것), 5 큰 압축, 데이터 파일(30일 넘고 50MB 넘는 것), 6 작업 폴더 저장소 안의 커밋되지 않은 목업, 캡처, 비교본(14일 넘은 것).

절대 지우지 않는 것: git으로 추적되는 파일, `_수신함`, `_발신함`, `_비밀`, `_할일`, 키와 인증서 같은 비밀값 파일, 캐시와 빌드 폴더. 스크립트가 이미 빼지만, 보여 줄 때 한 번 더 본다.

## 2. 보여 주기

- 첫 줄에 지금 남은 공간과, 묶음을 다 지우면 늘어날 크기를 쓴다.
- 묶음마다 `[1] 설치 파일 1.9GB, 12개: 예전에 받은 앱 설치 파일(IntelliJ, VS Code, Chrome …). 앱은 이미 설치돼 있어 지워도 됨` 꼴로, 무엇이고 지우면 무슨 일이 생기는지를 한 줄로 쓴다.
- 묶음 3과 6은 위치별 합계 상위 몇 개와 "최근 판 하나 남기기"를 권하는지 함께 쓴다.
- 지울지 애매한 것(최근 7일 안의 파일, 고객이 보낸 원본처럼 보이는 것)은 따로 짚는다.
- 마지막에 "어느 묶음을 지울까요? 번호로 알려 주세요(예: 1, 2, 3은 최근 판 남기고)"라고 묻는다. **사용자가 고르기 전에는 지우지 않는다.**

## 3. 지우기 (사용자가 고른 것만)

- `python3 ~/.claude/bin/cleanup-apply.py --groups <묶음> [--ids <번호>] [--keep-latest]`. 먼저 `--dry`로 지울 목록과 크기를 보여 줘도 된다.
- 기본은 **휴지통으로 옮기기**다(되살릴 수 있음). 휴지통을 비워야 공간이 생기므로, 끝나고 "휴지통을 비울까요?"를 묻고 사용자가 원하면 비운다. 사용자가 처음부터 "바로 지워"라고 하면 `--rm`을 쓴다.
- 스크립트는 지우기 직전에 파일이 그대로인지, git으로 추적되지 않는지 다시 확인하고 아니면 건너뛴다.
- 끝나면 `df -h /`로 늘어난 공간을 다시 재서 보고한다.

## 4. 보고

남은 공간 전과 후, 지운 묶음과 크기, 건너뛴 것과 이유, 휴지통에 남은 크기. 이 스킬은 캐시를 지우지 않는다는 점과, 더 비우려면 무엇이 남았는지(캐시, 빌드 폴더)를 한 줄로 덧붙인다.
